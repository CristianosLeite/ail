# AGENTS.md

This file provides guidance to AI coding agents when working with code in this repository.

## What this is

AIL is a proof-of-concept programming language whose design goal is low token consumption when an AI writes it. `docs/tokens.md` has the measured cost and what it decides: fewer lines matter more than shorter words, and a number costs more than a name. Write a test and its consequence as a block and a comparison with its jump as one statement; `tools/fuse.py` does both to an existing source. It is hardware-oriented (assembly-like, no classes or objects) and human readability is explicitly not a goal. When adding syntax, prefer short common words and bare spaces over punctuation and boilerplate, and let the compiler infer anything derivable (for example, a string literal supplies its own length).

The compiler is bootstrapped: stage0 (`stage0/ailc.s`) is written in assembly, and stage1 (`stage1/ailc.ai`) is the same compiler written in AIL, built by stage0 and then by itself. The two must behave identically, byte for byte, so a change to the language goes into both.

## Rules

- All repository text is in English: documentation, code comments, commit messages, test names, compiler messages and the knowledge base. This holds even when the conversation is in another language.

## Commands

Requires GNU `as` and `ld` on x86-64 Linux.

```
make            # build build/ailc, every example in examples/ and build/ailc1 (stage1)
make test       # run every test in tests/ and the I/O checks of tests/io.sh with stage0,
                # check a failed example build (tests/make.sh) and the generated
                # tables, compare the compilers (tests/stage1.sh),
                # check emitted bytes (tests/bytes.sh), fuzz both compilers against
                # each other (tests/fuzz.sh), then run tests and I/O checks with stage1
make fuzz N=50000 SEED=3   # a longer fuzz; a source the compilers differ on is kept in build/fuzz/
make test T=hello   # run one test, with both compilers
make build/foo  # compile examples/foo.ai to build/foo
make tables      # write stage1/tables.ai again from the tables of stage0/ailc.s
make clean
tools/tokens.sh  # token cost of examples/ against the C, Rust and assembly programs in bench/
tools/bench.sh   # check that bench/ behaves like examples/ (needs gcc and rustc)
python3 tools/fuse.py in.ai out.ai  # rewrite a source with compare-and-jump statements and if blocks
python3 tools/randvars.py build/ailc 300 1      # random programs against a computed result:
python3 tools/randvars.py build/ailc 300 2 top  # run after touching variable allocation
```

The compiler reads source on stdin and writes the executable on stdout. A `use "path"` in the source is opened relative to the directory the compiler runs in, so run it from the top of the repository for sources that use repository paths (stage1 and the tests do):

```
build/ailc < prog.ai > prog && chmod +x prog
```

`build/ailc1` is used the same way. Files that tests name with `use` are in `tests/lib/`. A test is a set of files `tests/<name>.*`, run by `tests/run.sh` (with the compiler named by `AILC`, default `build/ailc`):

- `.ai`: the program, or `.ai.sh`, a script that prints it (used for generated sources such as the size-limit tests)
- `.out`: expected stdout of the compiled program
- `.code`: expected exit status of the compiled program, default 0
- `.err`: expected compiler stderr; the compiler must then exit 1

A test has either `.err` (compiling must fail) or `.out` (the program must run). The runner kills a compiler or a program after 10 seconds, with `SIGKILL` to its whole process group, and fails the test, so a loop that never ends cannot hang the suite or outlive it. The compiler's I/O errors do not fit that form and are checked by `tests/io.sh`, which `make test` runs after the suite when no `T` is given: closed stdin, output to `/dev/full`, output to a pipe whose reader is gone, and a short write (a non-blocking pipe that takes 4096 bytes: the compiler must write that prefix, then report the error). `make test` names the compiler of every run itself, so an `AILC` in its environment changes nothing. `tests/stage1.sh` gives the source of every test and example to both compilers and requires the same stdout, stderr and exit status, then requires `build/ailc1` (stage1 built by stage0) and `build/ailc2` (stage1 built by itself) to be the same file. `tests/fuzz.sh` does the same comparison on sources made by random edits of the tests, examples and libraries (300 in `make test`, from a fixed seed; it never runs what it compiles). `tests/bytes.sh` is the one check that does not take a compiler's word for the output: for six programs that fill a fixup table to its capacity it computes the whole expected file in awk, header and every displacement, and compares; a second compiler must then give the same file. `tests/make.sh` runs `make` in a scratch copy to check what the Makefile does when an example fails to compile: the build fails each time it is tried, an executable from an earlier build stays as it was, and no temporary file is left.

Compiler errors are one line on stderr, `ailc: <place>: <message> <name>`, where the place is the line number, with `<path>:` in front for a line of a file named by `use`, and the name is given for the messages about one. The messages are `syntax error`, the more specific `unknown statement`, `not allowed here`, `missing end`, `missing as`, `unexpected as`, `missing label`, `wrong operand count`, `unterminated string` and `expected a name`, and `undefined variable`, `unassigned variable`, `too many variables`, `duplicate name`, `invalid access`, `number too big`, `buffers too big`, `undefined label`, `undefined function`, `wrong argument count`, `wrong result count` and `cannot read file`, all with exit status 1. `source too big` and `program too big` (status 1) and `read error` and `write error` (status 2) have no place. `docs/language.md` has the table of causes; a test's `.err` file holds the whole line.

## Library

`lib/io.ai` is AIL code that programs compile in with `use "lib/io.ai"`: `print`, `eprint`, `fdwrite`, `die`, `putn`, `strlen`, `argc` and `argv`. Its tests are the `lib_io_*` files in `tests/`. A new helper goes there only if several programs need it.

## Language

`docs/language.md` is the language reference, `docs/compiler.md` explains stage0 and `docs/stage1.md` stage1; keep them in sync with `stage0/ailc.s` and `stage1/ailc.ai`. Statements:

- `use "path"`: compiles another file at this place, once per path as written; top level only. All files together share the source limit.

- `sys n a b ...`: raw Linux syscall, up to 6 arguments; `n` is a number, a `const`, or one of the built-in syscall names (`read`, `write`, `open`, `close`, `mmap`, `exit`, ...; the list is in `docs/language.md`), which are names only in that place.
- `args as p`: at top level only, the address of argc, the argument addresses and the environment.
- `set a as x`, and `add sub mul div mod and or xor shl shr` as `op a b as x`: 64-bit, wrapping, unsigned division and shift.
- `eq ne lt le gt ge` as `op a b as x`: 64-bit comparison, unsigned order, result `1` or `0`.
- `fadd fsub fmul fdiv fsqrt`, `itof ftoi`, `flt fle feq`: the same values read as IEEE doubles; no float literals.
- `xadd p v as x`, `cas p old new as x`: atomic add (old value) and compare-and-swap (1 if stored) on the 64 bits at `p`.
- `sdiv smod sar` and `slt sle sgt sge`: the signed forms of `div mod shr` and of the four orderings. Nothing is checked: overflow wraps, a zero divisor is `SIGFPE`.
- `buf name size`: reserves zero-filled writable bytes (rounded up to 8); the name is a constant address. The size is a number or a `const` and may be 0.
- `local name size`: bytes in the frame of the function it stands in, not zero-filled, gone at return; the name is one of the function's variables but cannot be assigned.
- `alloc n as p`, `free p`: run-time storage, one `mmap` per call with a 16-byte length header; zero-filled, 16-byte aligned, `p` is 0 if the kernel refuses.
- `var a b c`: global 64-bit cells, zero at start, read as a value and written by `as`, visible in every function.
- `const name number`: a named number, usable as any value, as the `sys` number and as a `buf` size.
- `data name item ...`: read-only bytes from strings and byte values 0 to 255; the name is a constant address and is optional. Consecutive `data` lines are contiguous, so a table is one row a line. No limit on their number.
- `len x as n`: the length in bytes of a buffer (as declared), of a data name (its own line) or of a string.
- `at name i n as p`: the address `name + i`, with a run-time trap (`ud2`) unless `n` bytes from there lie inside the buffer, data run or local `name`.
- `load p as x`, `store p a`: 64-bit access at address `p`; `load4`/`store4`, `load2`/`store2` and `loadb`/`storeb` are the 32-bit, 16-bit and byte forms, loads zero-extended.
- `label name`, `jmp name`, `jz a name`, `jnz a name`: a label, and jumps to one always, if `a` is zero or if it is not (all 64 bits); labels may be used before they are defined.
- `jeq jne jlt jle jgt jge` and signed `jslt jsle jsgt jsge` as `op a b name`: compare and jump in one statement.
- `if a`, `ifz a`, `ifeq a b` and the other comparisons with the prefix `if`, then lines, an optional `else` and lines, then `end`: a block. `end` closes the innermost open block, and the function only when none is open.
- `fn name a b` ... `end`: a function with up to 64 parameters; top-level execution skips the body, functions do not nest, and reaching `end` returns 0. `ret a b` returns one to six values, the same number at every `ret` of the function, and is only allowed inside a function.
- `tail name a b`: calls a function and returns its result, releasing the current frame first; inside a function only, no `as`, at most six values.
- `call name a b as x y`: calls a function with as many values as it has parameters; `as` is optional and takes one name per result, at most as many as the function has; the function may be defined later.
- `ref name as p`, `callp p a b as x`: the address of a function, and a call through an address, unchecked.

Arguments are 64-bit integers (decimal, `0x` hexadecimal, or either after `-`; one that does not fit is `number too big`), string literals, variables or global names (`buf`, `data`, `var`, `const`); a string is two arguments, address then length, in `sys` and `call`, and its address alone in every other statement. `\xHH` in a string is the byte with that hexadecimal value. `as name` at the end of a statement keeps its result in a variable; that is the only way to set one besides being a parameter. A variable may only be read where every way to the line assigned it, and a jump back to a label must have assigned what the label had (`unassigned variable`). `as` is required on everything that produces a value, forbidden on stores, jumps and `ret`, and optional on `sys` and `call`. Variables are 64-bit, at most 64 at top level and 64 in each function (parameters included). Six registers hold them: at top level the first six variables, the rest live in memory cells; in a function a register is reused once its variable is no longer mentioned, and a variable without a free register lives on the stack. A function sees only its own variables and labels; `buf`, `data`, `var` and `const` names are global; a `buf` or `data` may be declared after its uses, a `var` or `const` must come first. At top level variables and global names share one name space; inside a function a parameter or variable hides a `buf`, `data` or `const` of the same name from its definition on, while `as` on a `var` name writes the cell. Labels and functions each have their own name space, with no limit on their number; keywords are only special at the start of a line. Tokens are separated by spaces or tabs only and may not touch; lines end with LF or CRLF; any other separator byte is a syntax error. `#` comments to end of line; a CR in a comment must still be followed by LF. Execution starts at the first line and `exit(0)` is appended.

## Compiler architecture (`stage0/ailc.s`)

GNU as, Intel syntax (`.intel_syntax noprefix`). One pass over the top level and two over each function, with no AST; the symbol tables are a variable table with 64 entries per scope, a table of global names, a label table and a function table, and the only fixups are jump and call displacements: it reads all of stdin into a buffer, emits machine code into an output buffer as it scans, and writes the buffer once at the end. Buffers never grow: the source may be 8 MiB (`INSZ`), every table is sized from that for the shortest line that adds an entry, and the output is 16 times as large and checked by `outchk`; untouched pages cost nothing.

- **Errors**: the stubs at the end (`fail` macro) leave the message in `rax`/`edx` and jump to `die_at` (place, no name), `die_name` (name in `r8`/`r9`), `die_plain` or `die_io` (no place). `die` writes the pieces to stderr. The place comes from `epos`: 0 means the input cursor in the unit `curunit`, -1 nowhere, anything else an address in the source, which the routines that run after parsing set from the name in their entry (`resolve`, the loops of `fin`; a `chks` entry carries the position of its statement). A new error needs a message (`msg`), a stub and, in stage1, a function of three lines.
- **Units**: a `use` reads its file into `inbuf` behind everything read so far (`srcend`), pushes cursor and unit end on `ustack` and scans the new bytes; `unitend` pops at the end of a unit or goes to `fin`. `uses` holds the paths seen. A function may not span units.
- **Output is a complete ELF64** emitted by the compiler itself: a 176-byte header template (ELF header plus two `PT_LOAD` segments) is copied in first, code follows at file offset 176. The file is `ET_DYN`: position-independent, loaded anywhere, with no address in any instruction. The first segment is the file, R+X; the second is R+W, has no file bytes, starts on the page after the code and holds the var cells and then the buffers. Its start (`rwstart`) is known only in `fin`, which fills in the `rel32` of every use recorded in `refs` and keeps the image within 2 GiB (`IMGMAX`).
- **Fixed register roles** throughout: `rsi`/`r15` input cursor and end, `rdi`/`r14` output cursor and base, `ebx` index of the next syscall argument, `ebp` number of variables defined in the current scope. Routines rely on these rather than passing parameters.
- **Statements are rows of `optab`**: keyword, operand count, two flag bytes and instruction bytes (`curop` points at the count, so the flags are at `+1`, the code length at `+3` and the code at `+4`). All eight flags of the first byte are taken; `IS_AT`, `IS_REF`, `IS_PTR`, `IS_IF` and `IS_TOP` are bits 0 to 4 of the second, and a new flag goes there too. Operands go through the same parser as syscall arguments, so they land in `rax` and `rdi`; `emit_op` then copies the row's bytes where `sys` gets its `syscall`, and the result is left in `rax` for `as`. `curop` points at the current row. `use`, `buf`, `data`, `var`, `const`, `local`, `label`, `fn`, `else` and `end` are the statements parsed on their own (`usedef`, `bufdef`, `datadef`, `vardef`, `constdef`, `localdef`, `labdef`, `fndef`, `elsedef`, `fnend`).
- **Syscall names**: `sysname` reads the number of `sys` when it is a name: a const of the program, or else an entry of the table `sysnames` (length, name, two-byte number). A syscall added there is added to `stage1/tables.ai` and to the table in `docs/language.md`.
- **Arguments** are emitted by `emit_mov` into the register of the argument position (rax, rdi, rsi, rdx, r10, r8, r9) in the shortest of three forms: `mov r32, imm32` from `regtab` below 2^32, `mov r64, imm32` when sign extension gives the value, else `mov r64, imm64`. `rdnum` reads every integer and reports `number too big`. A fixup of `refs` relies on the first form and takes the address of the `imm32` from `immpos`, since a `push` may follow the `mov`.
- **Variables** live in the generated program's `rbx`, `rbp`, `r12`, `r13`, `r14`, `r15` (table `varnum`) or in memory. The compiler's table `vars` stores each name as a pointer into the input buffer plus a length; its first half is the top level and its second half the function being compiled (`infn`), and `defvar` finds or adds a name in the current half. `varplace` gives the place of a variable and `emit_varmov` the `mov` between it and a register (`emit_mov_rr`, or `emit_mem` for a cell or a stack slot). At top level variables 7 to 64 get a cell of their own (`topcell`, a cell number).
- **Functions are compiled twice.** `fndef` snapshots the cursors and counters in `snap` and sets `pass` to 1; that pass emits throwaway code, reports every error and records per variable its first and last mention (`vfirst`, `vlast`) and per backward jump a loop (`loops`, from `labpos`). At `end`, `alloc` stretches every range that meets a loop to the loop's end, then gives each variable the first register or stack slot whose previous variable is done (`fnloc`, `fnslots`); `fnend` restores the snapshot and jumps back to `fndef` with `pass` 2. Anything a statement adds to compiler state inside a function must be in the snapshot, or it is added twice. Slots are `[rsp + 8k]`, reserved after the pushes and released before each return by `emit_frame`. A `local` is a variable with an offset in `vlocal` and no place: `varplace` gives its distance from `rsp`, above the slots, and reading it is a `lea`; the frame is `8 * fnslots + fnlocal`. `clrloc` must not run between the first pass and `alloc`.
- **Buffers** are places in the writable segment (tables `bufs`, `bufaddr` and `bufsize`, total in `bsssz`). A use of a buffer or data name is `lea reg, [rip+rel32]` from `emit_lea` plus a `refs` entry of kind 0; `bufaddr` holds the distance from the first buffer, or for data the file offset. The same tables hold every global name, with its kind in `bufkind` (`G_ADDR` buffer or data, `G_VAR`, `G_CONST`), and are sized from the source limit; `newglob` enters a name after the duplicate checks. A `var` is a numbered cell at the start of the writable segment, read by `ident` with `mov r64, [rip+rel32]` and written by `capture` with the store form, both through `emit_mem`, which records a `refs` entry of kind 3 with the cell number. A `const` keeps its value in `bufsize`.
- **Known addresses**: `opd` (first two values of the statement) and `vk` (each variable of the scope) hold what is known of a value: a number, a global name plus a number, or a string. `propagate` carries it through `set`, `add` and `sub`, which it recognises by their row bytes; `clrvk` forgets at a label and at `end`. Rows flagged `IS_MEM` (loads and stores; width from the last letter of the keyword) go through `memchk`: a string is checked at once, a name is recorded in `chks` and checked by `fin` against the declared size of the buffer or the run of the data name (`bufrun`, `runend`), reporting `invalid access`. `nchks` and `nruns` are part of the function snapshot.
- **Assigned variables**: `asg` is a 64-bit mask of the variables assigned on every way to the current line; `ident` checks it on a read, `capture` and parameters set it. A jump stores it in its `fixs` entry; `label` ands the masks of the jumps seen so far into it (`labasg`) and keeps the result in `labmask`; a backward jump must contain the `labmask` of its label. After `jmp` and `ret`, `godead` sets all bits until the next label; a label reached only from below starts from `jmask`. `fndef` and `fnend` save and restore the three cells in `topasg`.
- **Finding names**: labels, functions and global names go through one hash (`buckets`, `hnodes`; `hfind`, `hadd`), keyed by kind, scope and name; `lookup_label`, `lookup_fn` and `lookup_buf` wrap it. A table entry needs a node to be found: `globdone` adds the one of a global name when its statement is complete. Each pass over a function has its own `scope` number, the node count is in the function snapshot and `hundo` removes the nodes of the first pass. A jump to a label not yet defined keeps the and of `asg` in a pending node, which `labasg` reads.
- **Labels and jumps**: `label` records the output cursor under its name (tables `labels` and `labaddr`). `jmp`, `jz` and `jnz` are `optab` rows flagged `IS_JMP` whose bytes stop before the `rel32`; the name after their operands is taken as a label by `jtarget`, which appends the name and the `rel32` address to `fixs`. `resolve` fills in every jump of the current scope, backward ones included, and reports `undefined label`; `fin` calls it for the top level and `end` for a function. Both tables are sized from the source limit and cannot overflow.
- **Blocks**: rows flagged `IS_IF` end before the `rel32` of the opposite jump; at the end of such a statement `arg` pushes the `rel32` address and `asg` on `blks`. `end` with a block open (`nblk` above `blkbase`) goes to `blkend`, which fills in the jump and merges `asg` with the recorded mask; `else` (`elsedef`) emits a `jmp`, retargets the entry and remembers how the first part ended. No label is created.
- **Functions**: `fn` emits a `jmp rel32` over the body (patched by `end`), then the entry: one `push` for each of the variable registers the function uses (`fnregs`, counted by `alloc`; `pushlen` gives the bytes), `sub rsp` for the frame if any (a frame of a page or more through the template `probe`, which touches every page), and one `mov` per parameter from its argument register (`rax`, `rdi`, `rsi`, `rdx`, `r10`, `r8`). It saves `ebp` and remembers where the function's labels and jumps start (`labbase`, `fixbase`); `end` emits `xor eax, eax` and the epilogue, resolves the function's jumps and cuts `labels` and `fixs` back, which is what makes labels local. `ret` is an `optab` row (`IS_RET`) whose bytes are the six `pop`s and `ret`; `popskip` says how many of those bytes to leave out. `tail` has the flags of `call` and `ret` and the bytes of the pops plus `E9`. `call` is a row flagged `IS_CALL`: values after the sixth are loaded into `r11` (row 7 of `regtab` and `argnum`, chosen by `argidx`) and pushed by `argnext`, which counts the bytes in `pushed`; `varplace` adds `pushed` to stack-slot distances and `emit_op` emits `add rsp` after the call. The callee loads those parameters from above its frame, which needs `fnnpar` from the first pass. `next` reads the function name into `callname`, and `emit_op` appends name, `rel32` address and value count to `calls`, which `fin` resolves against `funcs`, `funaddr` and `funargs`, reporting `undefined function`, `wrong argument count` and `wrong result count` (`funres` against the names after `as`, which `capture` collects in `caps`). `ref` is a call entry with the count -1 and gets an absolute address; `callp` (`IS_PTR`) puts its first value in `rcx`, row 8 of `regtab`, and is not recorded.
- **Strings and data** are inlined in the code stream behind a `jmp rel32`; a string is addressed by a `lea` whose distance is known at once, so no data section or second pass is needed. The code segment is not writable, so they are read-only. `strbytes` copies the bytes of a literal for both. A `data` statement that starts where the previous one ended (`dataend`) appends to it and rewrites that jump (`datarel`) instead of emitting its own; `label` clears `dataend`, so a label after data stays the address of code. The row flag `IS_LEN` makes an operand its length instead of its address, and `IS_AT` makes the first one (`atname`) two values, address and size; the size of a global name is a `refs` fixup of kind 2, the bytes to the end of its object.

Adding a statement that takes values in `rax`/`rdi` and leaves a result in `rax` means adding a row to `optab` and running `make tables`; anything else needs a keyword check in `next` (as `buf`, `data`, `var`, `const`, `local`, `label`, `fn` and `end` have) and its own parser ending in `eol`. Either way add tests for what it accepts and rejects. Do not name a label after an assembler keyword: `jbe word` assembles without a warning and jumps to the wrong place. Forward references go through a fixup list: `fixs` holds the `rel32` jump displacements to labels of the current scope, `calls` the `rel32` displacements of calls, `refs` every place that `fin` must fill in once the layout is known: kind 0 the `rel32` of an address of a buffer or data name, 1 and 2 the `imm32` of a length (`len`, `at`), 3 the `rel32` of a var cell; `fin` resolves `refs` last and reports `undefined variable` there. `jtarget` relies on `eol` and `emit_op` keeping `r8` and `r9`, the label name.

## Stage1 (`stage1/ailc.ai`)

A translation of stage0, routine by routine; `docs/stage1.md` has the map. What to know before editing it:

- **The top level is the state machine** of stage0 under the same labels (`next`, `tokend`, `arg`, `num`, `str`, `ident`, `capture`, `bufdef`, `localdef`, `vardef`, `constdef`, `datadef`, `labdef`, `jtarget`, `fndef`, `fnend`, `fin`) and uses only the variables `c d r f p q`, which have registers; a seventh would work but live in memory. Everything stage0 calls is a function.
- **Global state is in `var`s**, since a function sees no top-level variable: `ip`, `ie`, `op`, `ai`, `nv`, `cur`, `ns`, `nl` for the fixed registers of stage0 and its counters under their own names (`nbufs`, `infn`, `nfix`, ...). `as` on one of those names writes the global, so no function may use them for a local. The tables are buffers (`vars`, `globs`, `labs`, `fixs`, `funs`, `calls`).
- **Errors are calls that never return** (`call err`, `call edup`, ...); `ok` and `no` are a syntax error unless their value is non-zero or zero. A lookup returns -1 for a name that is not defined.
- **The read-only tables** (ELF header, statement rows, register tables, syscall names) are `data` lines in `stage1/tables.ai`, which `stage1/ailc.ai` names with `use` in its last line. That file is generated: `tools/tables.sh` (`make tables`) writes it from the bytes that `stage0/ailc.s` assembles to, under the names of stage0, one row a line. Never edit it by hand; change the table in stage0 and run `make tables`. `tests/tables.sh`, part of `make test`, fails when the file is out of date. The statement table of stage0 ends with ten rows for the statements that are parsed on their own (`fn`, `buf`, `end`, `label`, `data`, `var`, `const`, `local`, `use`, `else`), flags 255, which only stage1 reaches.
- The buffer sizes are those of stage0 for `INSZ` = 8 MiB, as plain numbers; when a table of stage0 changes its entry size or count, change the matching `buf`.
