# AGENTS.md

This file provides guidance to AI coding agents when working with code in this repository.

## What this is

AIL is a proof-of-concept programming language whose design goal is low token consumption when an AI writes it. `docs/tokens.md` has the measured cost and what it decides: fewer lines matter more than shorter words, and a number costs more than a name. Write a computation as an expression (`x=a+b*c`, `x+=1`, `store p+8 n/10`, no spaces in it), a test and its consequence as a block (`if a<b`), and a loop as `while`; `tools/infix.py` rewrites an existing source that way, and `tools/fuse.py` makes blocks out of labels and jumps. It is hardware-oriented (assembly-like, no classes or objects) and human readability is explicitly not a goal. When adding syntax, prefer short common words and bare spaces over punctuation and boilerplate, and let the compiler infer anything derivable (for example, a string literal supplies its own length).

The compiler is written in AIL: `stage1/ailc.ai`, with its tables in `stage1/tables.ai`. It was translated from a compiler in assembly, stage0, which built it first and was removed on 2026-11-20; the directory name stayed. The build starts from a seed, a released executable of stage1 that `seed/MANIFEST` pins by version, source revision and SHA-256 (`tools/seed.sh` takes it from `seed/ailc-<version>` or fetches it with `curl` or `gh`), and compiles the source in three generations, `build/ailc1` by the seed, `build/ailc` by that and `build/ailc2` by `build/ailc`; the last two must be the same file. `stage1/ailc.ai` may therefore use only what the pinned seed understands; since seed 2 that includes expressions, `x=e` and `while`, and the source is written with them.

## Rules

- All repository text is in English: documentation, code comments, commit messages, test names, compiler messages and the knowledge base. This holds even when the conversation is in another language.

## Commands

Requires x86-64 Linux, `python3` for `make test`, and the seed: a local `seed/ailc-<version>`, or `curl` or `gh` and network to fetch it once.

```
make            # build build/ailc (from the seed) and every example in examples/
make test       # run every test in tests/ and the I/O checks of tests/io.sh,
                # check a failed example build (tests/make.sh), the form of the
                # tables (tests/tables.sh), instruction bytes (tests/insn.sh) and
                # emitted files (tests/bytes.sh), compare the compiler with its
                # seed-built translation and check the fixed point (tests/self.sh),
                # fuzz it (tests/fuzz.sh), check the rewriting tool (tests/infix.sh)
                # and run random programs against a computed result
                # (tools/randvars.py; both need python3)
make fuzz N=50000 SEED=3   # a longer fuzz; a source that fails is kept in build/fuzz/
make test T=hello   # run one test
make build/foo  # compile examples/foo.ai to build/foo
make clean
tests/insn.sh hex 'shr rax, 13'   # the bytes GNU as writes for instructions, for a case in tests/insn.cases
tests/insn.sh asm   # check tests/insn.cases against the assembler
tools/tokens.sh  # token cost of examples/ against the C, Rust and assembly programs in bench/
tools/bench.sh   # check that bench/ behaves like examples/ (needs gcc and rustc)
python3 tools/perf.py   # time examples/ against bench/ built with gcc -O3 and rustc -O; docs/performance.md
python3 tools/fuse.py in.ai out.ai  # rewrite a source with compare-and-jump statements and if blocks
python3 tools/infix.py in.ai out.ai  # rewrite statements as expressions, label loops as while, fold temporaries
python3 tools/randvars.py build/ailc 2000 1      # more random programs than make test runs:
python3 tools/randvars.py build/ailc 2000 2 top  # run after touching variable allocation
```

The compiler reads source on stdin and writes the executable on stdout. A `use "path"` in the source is opened relative to the directory the compiler runs in, so run it from the top of the repository for sources that use repository paths (the compiler's own source and the tests do):

```
build/ailc < prog.ai > prog && chmod +x prog
```

Files that tests name with `use` are in `tests/lib/`. A test is a set of files `tests/<name>.*`, run by `tests/run.sh` (with the compiler named by `AILC`, default `build/ailc`):

- `.ai`: the program, or `.ai.sh`, a script that prints it (used for generated sources such as the size-limit tests)
- `.out`: expected stdout of the compiled program
- `.code`: expected exit status of the compiled program, default 0
- `.err`: expected compiler stderr; the compiler must then exit 1

A test has either `.err` (compiling must fail) or `.out` (the program must run). The runner kills a compiler or a program after 10 seconds, with `SIGKILL` to its whole process group, and fails the test, so a loop that never ends cannot hang the suite or outlive it. The compiler's I/O errors do not fit that form and are checked by `tests/io.sh`, which `make test` runs after the suite when no `T` is given: closed stdin, output to `/dev/full`, output to a pipe whose reader is gone, and a short write (a non-blocking pipe that takes 4096 bytes: the compiler must write that prefix, then report the error). `make test` names the compiler of every run itself, so an `AILC` in its environment changes nothing. `build/ailc1` and `build/ailc` are the same source in two translations, by the seed and by the compiler the seed built, so they must behave alike: `tests/self.sh` gives the source of every test and example to both and requires the same stdout, stderr and exit status, then requires `build/ailc` and `build/ailc2` (the source compiled by `build/ailc`) to be the same file. That comparison is trivial while the seed is the current compiler and is the check of self-compilation once the compiler writes other code than the seed. `tests/fuzz.sh` gives both sources made by random edits of the tests, examples and libraries (300 in `make test`, from a fixed seed; it never runs what it compiles) and requires, besides the same behaviour, that the compiler ends properly: status 0 with an executable and no message, or status 1 with one `ailc: ` line and no output. `tools/randvars.py` builds random programs of arithmetic with every operator, loops and blocks with an `else`, writes each one three times from the same tree, with statements, labels and jumps, line for line the same with each statement spelled as an expression, and with nested expressions, `x+=e`, `while` and `if` on a comparison, computes in Python the exit status all must give, requires the first two to compile to the same bytes, and runs them, 200 in a function and 200 at top level; a program that fails is kept in `build/randvars/`. `tests/insn.sh` and `tests/bytes.sh` are the checks that do not take a compiler's word for the output. `tests/insn.sh` compiles each source of `tests/insn.cases` and requires the code between the header and the final exit to be the hex beside it, which GNU `as` wrote from the instructions in the third column; there is a case for every row of the statement table and for the other tables, and a new or changed row needs one. `tests/tables.sh` checks the form of `stage1/tables.ai`: lengths, names that occur once, flags, table sizes, and the syscall numbers against a list of its own. `tests/bytes.sh` looks at whole files: for six programs that fill a fixup table to its capacity it computes the whole expected file in awk, header and every displacement, and compares; the seed-built translation must then give the same file. `tests/infix.sh` checks `tools/infix.py` on the fixture `tests/infix/in.ai`: it must give `tests/infix/out.ai`, leave that unchanged when run again, and both must be the same program. `tests/make.sh` runs `make` in a scratch copy to check what the Makefile does when an example fails to compile: the build fails each time it is tried, an executable from an earlier build stays as it was, and no temporary file is left.

Compiler errors are one line on stderr, `ailc: <place>: <message> <name>`, where the place is the line number, with `<path>:` in front for a line of a file named by `use`, and the name is given for the messages about one. The messages are `syntax error`, the more specific `unknown statement`, `not allowed here`, `missing end`, `missing as`, `unexpected as`, `missing label`, `wrong operand count`, `unterminated string` and `expected a name`, and `undefined variable`, `unassigned variable`, `too many variables`, `duplicate name`, `invalid access`, `number too big`, `buffers too big`, `undefined label`, `undefined function`, `wrong argument count`, `wrong result count` and `cannot read file`, all with exit status 1. `source too big` and `program too big` (status 1) and `read error` and `write error` (status 2) have no place. `docs/language.md` has the table of causes; a test's `.err` file holds the whole line.

## Library

`lib/io.ai` is AIL code that programs compile in with `use "lib/io.ai"`: `print`, `eprint`, `fdwrite`, `die`, `putn`, `strlen`, `argc` and `argv`. Its tests are the `lib_io_*` files in `tests/`. A new helper goes there only if several programs need it.

## Language

`docs/language.md` is the language reference and `docs/compiler.md` explains the compiler; keep them in sync with `stage1/ailc.ai`. Statements:

- `use "path"`: compiles another file at this place, once per path as written; top level only. All files together share the source limit.

- `sys n a b ...`: raw Linux syscall, up to 6 arguments; `n` is a number, a `const`, or one of the built-in syscall names (`read`, `write`, `open`, `close`, `mmap`, `exit`, ...; the list is in `docs/language.md`), which are names only in that place.
- `args as p`: at top level only, the address of argc, the argument addresses and the environment.
- `x=e` keeps the expression `e` in `x` as `set e as x` does, and `x+=e`, with any of `* / % + - << >> & ^ |` before the `=`, changes `x` in place by the whole of `e`. One word, no space; the name is read before statements are looked up, so it may be a keyword.
- `set a as x`, and `add sub mul div mod and or xor shl shr` as `op a b as x`: 64-bit, wrapping, unsigned division and shift.
- `eq ne lt le gt ge` as `op a b as x`: 64-bit comparison, unsigned order, result `1` or `0`.
- `fadd fsub fmul fdiv fsqrt`, `itof ftoi`, `flt fle feq`: the same values read as IEEE doubles; no float literals.
- `xadd p v as x`, `cas p old new as x`: atomic add (old value) and compare-and-swap (1 if stored) on the 64 bits at `p`.
- `sdiv smod sar` and `slt sle sgt sge`: the signed forms of `div mod shr` and of the four orderings. Nothing is checked: overflow wraps, a zero divisor is `SIGFPE`.
- `buf name size`: reserves zero-filled writable bytes (rounded up to 8); the name is a constant address. The size is a number or a `const` and may be 0.
- `local name size`: bytes in the frame of the function it stands in, not zero-filled, gone at return; the name is one of the function's variables but cannot be assigned.
- `alloc n as p`, `free p`: run-time storage, one `mmap` per call with a 16-byte length header; zero-filled, 16-byte aligned, `p` is 0 if the kernel refuses.
- `var a b c`: global 64-bit cells, zero at start, read as a value and written by `as`, visible in every function.
- `const name number`: a named number, usable as any value, as the `sys` number and as a `buf` size.
- `data name item ...`: read-only bytes from strings and byte values 0 to 255; the name is a constant address and is optional. Consecutive `data` lines are contiguous, so a table is one row a line. No limit on their number.
- `len x as n`: the length in bytes of a buffer (as declared), of a data name (its own line) or of a string.
- `at name i n as p`: the address `name + i`, with a run-time trap (`ud2`) unless `n` bytes from there lie inside the buffer, data run or local `name`.
- `load p as x`, `store p a`: 64-bit access at address `p`; `load4`/`store4`, `load2`/`store2` and `loadb`/`storeb` are the 32-bit, 16-bit and byte forms, loads zero-extended.
- `label name`, `jmp name`, `jz a name`, `jnz a name`: a label, and jumps to one always, if `a` is zero or if it is not (all 64 bits); labels may be used before they are defined.
- `jeq jne jlt jle jgt jge` and signed `jslt jsle jsgt jsge` as `op a b name`: compare and jump in one statement.
- `if a`, `ifz a` (where `a` may be a comparison, `if a<b`, at the cost of `iflt a b`), `ifeq a b` and the other comparisons with the prefix `if`, then lines, an optional `else` and lines, then `end`: a block. `end` closes the innermost open block, and the function only when none is open.
- `while a`, then lines, then `end`: a loop that runs while `a` (one value, usually an expression such as `i<n`) is not zero, tested before each round. A block like `if`, without `else`; after it only what was assigned before it is assigned.
- `fn name a b` ... `end`: a function with up to 64 parameters; top-level execution skips the body, functions do not nest, and reaching `end` returns 0. `ret a b` returns one to six values, the same number at every `ret` of the function, and is only allowed inside a function.
- `tail name a b`: calls a function and returns its result, releasing the current frame first; inside a function only, no `as`, at most six values.
- `call name a b as x y`: calls a function with as many values as it has parameters; `as` is optional and takes one name per result, at most as many as the function has; the function may be defined later.
- `ref name as p`, `callp p a b as x`: the address of a function, and a call through an address, unchecked.

Arguments are 64-bit integers (decimal, `0x` hexadecimal, or either after `-`; one that does not fit is `number too big`), string literals, variables, global names (`buf`, `data`, `var`, `const`) or expressions: values joined by `* / %`, `+ -`, `<< >>`, `&`, `^`, `|` and the comparisons `== != < <= > >=`, tightest first and left to right, with parentheses, written without a space (`b+8*(n-1)`), not where a name is required and not for the number of `sys`; a string is two arguments, address then length, in `sys` and `call`, and its address alone in every other statement. `\xHH` in a string is the byte with that hexadecimal value. `as name` at the end of a statement keeps its result in a variable; that and `name=expression` are the only ways to set one besides being a parameter. A variable may only be read where every way to the line assigned it, and a jump back to a label must have assigned what the label had (`unassigned variable`). `as` is required on everything that produces a value, forbidden on stores, jumps and `ret`, and optional on `sys` and `call`. Variables are 64-bit, at most 64 at top level and 64 in each function (parameters included). Six registers hold them: at top level the first six variables, the rest live in memory cells; in a function a register is reused once its variable is no longer mentioned, and a variable without a free register lives on the stack. A function sees only its own variables and labels; `buf`, `data`, `var` and `const` names are global; a `buf` or `data` may be declared after its uses, a `var` or `const` must come first. At top level variables and global names share one name space; inside a function a parameter or variable hides a `buf`, `data` or `const` of the same name from its definition on, while `as` on a `var` name writes the cell. Labels and functions each have their own name space, with no limit on their number; keywords are only special at the start of a line. Tokens are separated by spaces or tabs only and may not touch; lines end with LF or CRLF; any other separator byte is a syntax error. `#` comments to end of line; a CR in a comment must still be followed by LF. Execution starts at the first line and `exit(0)` is appended.

## Compiler architecture (`stage1/ailc.ai`)

`docs/compiler.md` explains it at length. One pass over the top level and two over each function, with no AST; the symbol tables are a variable table with 64 entries per scope, a table of global names, a label table and a function table, and the only fixups are jump and call displacements: it reads all of stdin into a buffer, emits machine code into an output buffer as it scans, and writes the buffer once at the end. Buffers never grow: the source may be 8 MiB (`inmax` is one byte more), every table is a `buf` sized from that for the shortest line that adds an entry, as a plain number with the count in its comment, and the output is 16 times as large and checked by `ochk`; untouched pages cost nothing. When an entry changes its size or a shorter line can add one, change the `buf`.

- **The top level is the state machine**, its states labels that jump to each other (`next`, `tokend`, `arg`, `num`, `str`, `ident`, `atname`, `capture`, `usedef`, `uend`, `bufdef`, `localdef`, `vardef`, `constdef`, `datadef`, `labdef`, `jtarget`, `fndef`, `fnend`, `blkend`, `elsedef`, `fin`), and uses only the variables `c d r f p q`, which have registers; a seventh would work but live in memory. Everything else is a function.
- **Global state is in `var`s**, since a function sees no top-level variable: `ip` and `ie` the input cursor and end, `op` the output cursor, `ai` the index of the next argument of the statement, `nv` the number of variables defined in the current scope, `cur` the row of the statement, `ns` and `nl` the name read last, and the counters under their own names (`nbufs`, `infn`, `nfix`, ...). `as` on one of those names writes the global, so no function may use them for a variable of its own. The tables are buffers (`vars`, `globs`, `labs`, `fixs`, `funs`, `calls`, `refs`, `chks`, `blks`); an entry holds all the fields of its name.
- **Errors are calls that never return** (`call err`, `call edup`, ...): a function of three lines per message sets the name at fault (`ename`, `enamel`) or drops the place and calls `die`, which writes the pieces to stderr. `ok` and `no` are a syntax error unless their value is non-zero or zero. A lookup returns -1 for a name that is not defined. The place comes from `epos`: 0 means the input cursor in the unit `curunit`, -1 nowhere, anything else an address in the source, which the routines that run after parsing set from the name in their entry (`resolve`, the loops of `fin`; a `chks` entry carries the position of its statement). A new error needs its function and a line in `docs/language.md`.
- **Units**: a `use` reads its file into `in` behind everything read so far (`srcend`), pushes cursor and unit end on `ustack` and scans the new bytes; `uend` pops at the end of a unit or goes to `fin`. `uses` holds the paths seen. A function may not span units.
- **Output is a complete ELF64** emitted by the compiler itself: a 176-byte header template (ELF header plus two `PT_LOAD` segments) is copied in first, code follows at file offset 176. The file is `ET_DYN`: position-independent, loaded anywhere, with no address in any instruction. The first segment is the file, R+X; the second is R+W, has no file bytes, starts on the page after the code and holds the var cells and then the buffers. Its start (`rwstart`) is known only in `fin`, which fills in the `rel32` of every use recorded in `refs` and keeps the image within 2 GiB .
- **Statements are rows of `optab`**: keyword, operand count, two flag bytes and instruction bytes (`cur` points at the count, so the flags are at `+1`, the code length at `+3` and the code at `+4`). The flags are numbers in `stage1/tables.ai`; `docs/compiler.md` names the bits. All eight of the first byte are taken (1 `AS_REQ`, 2 `AS_NONE`, 4 `IS_SYS`, 8 `IS_JMP`, 16 `IS_CALL`, 32 `IS_RET`, 64 `IS_LEN`, 128 `IS_MEM`); `IS_AT`, `IS_REF`, `IS_PTR`, `IS_IF` and `IS_TOP` are bits 0 to 4 of the second, and a new flag goes there too. A first byte of 255 marks a statement parsed on its own, numbered by its operand count: 1 `fn`, 2 `buf`, 3 `end`, 4 `label`, 5 `data`, 6 `var`, 7 `const`, 8 `local`, 9 `use`, 10 `else`, 11 `while`; `next` has a `jeq` per number and falls into `whiledef` for any other. Operands go through the same parser as syscall arguments, so they land in `rax` and `rdi`; `eop` then copies the row's bytes where `sys` gets its `syscall`, and the result is left in `rax` for `as` (the statements that only compute or compare take another way, see Expressions). `kw` finds the row of a keyword.
- **Syscall names**: `sname` reads the number of `sys` when it is a name: a const of the program, or else an entry of the table `sysnames` (length, name, two-byte number). A syscall added there is added to the list in `tests/tables.sh` and to the table in `docs/language.md`.
- **Arguments** are emitted by `mov` into the register of the argument position (rax, rdi, rsi, rdx, r10, r8, r9) in the shortest of three forms: `mov r32, imm32` from `regtab` below 2^32, `mov r64, imm32` when sign extension gives the value, else `mov r64, imm64`. `rdnum` reads every integer and reports `number too big`. A fixup of `refs` relies on the first form and takes the address of the `imm32` from `immpos`, since a `push` may follow the `mov`.
- **Variables** live in the generated program's `rbx`, `rbp`, `r12`, `r13`, `r14`, `r15` (table `varnum`) or in memory. The table `vars` stores each name as a pointer into the input buffer plus a length; its first half is the top level and its second half the function being compiled (`infn`), and `defvar` finds or adds a name in the current half. `vplace` gives the place of a variable and `vmov` the `mov` between it and a register (`mrr`, or `emem` for a cell or a stack slot). At top level variables 7 to 64 get a cell of their own (`topcell`, a cell number).
- **Functions are compiled twice.** `fndef` snapshots the cursors and counters in the vars `sip` to `sdr`, `snk`, `snu` and `snh` and sets `pass` to 1; that pass emits throwaway code, reports every error and records per variable its first and last mention (`vfirst`, `vlast`) and per backward jump a loop (`loops`, from the source position in the `labs` entry). At `end`, `alloc` stretches every range that meets a loop to the loop's end, then gives each variable the first register or stack slot whose previous variable is done (`fnloc`, `fnslots`); `fnend` restores the snapshot and jumps back to `fndef` with `pass` 2. Anything a statement adds to compiler state inside a function must be in the snapshot, or it is added twice. Slots are `[rsp + 8k]`, reserved after the pushes and released before each return by `frame`. A `local` is a variable with an offset in `vlocal` and no place: `vplace` gives its distance from `rsp`, above the slots, and reading it is a `lea`; the frame is `8 * fnslots + fnlocal`. `clrloc` must not run between the first pass and `alloc`.
- **Buffers** are places in the writable segment (table `globs`, total in `bsssz`). A use of a buffer or data name is `lea reg, [rip+rel32]` from `elea` plus a `refs` entry of kind 0; the entry holds the distance from the first buffer, or for data the file offset. The same table holds every global name, with its kind (address, var or const), and is sized from the source limit; `newglob` enters a name after the duplicate checks. A `var` is a numbered cell at the start of the writable segment, read by `ident` with `mov r64, [rip+rel32]` and written by `capture` with the store form, both through `emem`, which records a `refs` entry of kind 3 with the cell number. A `const` keeps its value in the size field.
- **Expressions**: an argument whose token starts with `(` or has, after its first byte, a byte that no name or number has (`excomp`) goes from `arg` to the state `earg`; every other token takes the old paths, so sources without expressions compile to the same bytes. `exparse` reads it with two stacks and no recursion (`exs` operators and open parentheses, `exv` values with what is known of each) into `ex`, a list of 32-byte nodes in stack-machine order: number, global name plus number, variable, var cell, or operator with the node of its left operand, the right one being the node before it. `exred` applies an operator and folds two numbers (`exfold`) or a name and a number; `exprec` gives the binding strength, `exname` resolves a name as `ident` does, `xgen` computes what is left as a stack machine whose stack the compiler keeps in `exv`: a number, variable, var or address stays what it is until its operator comes, which takes a number as an immediate and a variable in its register or in memory (nothing in an expression assigns, so that is safe), a computed value sits in a register from `xfree` (scratch registers that hold no value of the statement, never `rcx` or `rdx`; order in `xord`, `xpref` first) or is pushed when none is free (`xalloc`, `xspl`, `xpop2`; `pushed` kept exact). `xop` picks `xarith` (`+ - & ^ |` and `imul`, with `reg`, `imm` or memory as second operand, as `xsrc` classifies it; `xmuli` for variable times number), `xshift` (immediate count, or `rcx`), `xdiv` (shift or mask for a power of two, else `rax`/`rdx`, `xtake`) or `xcmpv` (`xcmp`, `setcc`); opcodes are in the table `xopc`, encodings are the shortest, as an assembler writes them. `xfin` puts the result in its register. `exarg` makes the result the next value of the statement, with the registers of earlier values out of the free set and `rax`/`rdx` (if it divides) or `rcx` (if it shifts under `callp`) pushed around the computation, and copies what is known of it to `opd`. **The statements that only compute or compare are compiled like expressions**, unless their line has a string: `xclass`, called in `next`, sets `xst` to 1 for `set` and the sixteen statements whose operators an expression has (`xso`; rows in `xrows`), 2 for those that compare two values and jump or open a block, 3 for `jz`, `jnz`, `if`, `ifz` (and `while`), 4 for the loads and 5 for the stores. `arg` then sends each value to the state `xarg`, which only parses it (`exparse` on top of the values before). At `as`, `xcap` applies the operator with `exred` and stores with `xstore`, as `exasn` does, so `add a b as x` and `x=a+b` are the same bytes; at the label or the end of the line, `xjcond` compares the two sides where they are (`xcmp`) or tests the one value in a register (`test reg, reg`) and sets `xskip` so that `eop` copies only the jump of the row; for a statement of kind 3 whose value is a comparison it first makes the statement the row that compares and jumps (`iflt`, `jge`, ...; name built in `exnm`). A load ends in `xmload` and a store in `xmstore` (before `eop`, which still runs `memchk` on what they put in `opd`): `xaddr` computes the address as base, index and number (`xmb`, `xmx`, `xmd`: a number added last, a variable with a register added last, the rest in a register), and `xmins` writes one `mov` or `movzx` with that operand (`erexm`, `emodm`), a store of a number that fits as an immediate. The instruction bytes of those rows are only used by lines with a string. An assignment is found in `next` by `exasg` before the keyword lookup and compiled by `exasn` (state `asgn`), which defines the variable first (`defv`, `defvar` for a name already read) and stores as `capture` does. A variable with a register is computed there (`xtr`): if no variable of the expression lives in that register it joins `xfree` as the preferred one; otherwise only the last operator (`xlast`) writes it, in place when an operand lives there (`x+=1` is `add rbx, 1`) or after loading the left operand, unless the right one is in it (`xdst`, `xint`, `xswap`); `xtarget` sets `xtin` and takes the register out of `xfree`. `movi`, `lear` and `xld` load into any register, where `mov`, `elea` and `ldvar` load into the register of the next argument; `orr`, `ori`, `rexw`, `modrr`, `epush`, `epop` and `esetcc` encode for any register.
- **Known addresses**: `opd` (first two values of the statement) and `vk` (each variable of the scope) hold what is known of a value: a number, a global name plus a number, or a string. `prop` carries it through `set`, `add` and `sub`, which it recognises by their row bytes; `clrvk` forgets at a label and at `end`. Rows flagged `IS_MEM` (loads and stores; width from the last letter of the keyword) go through `memchk`: a string is checked at once, a name is recorded in `chks` and checked by `fin` against the declared size of the buffer or the run of the data name (`runend`), reporting `invalid access`. `nchks` and `nruns` are part of the function snapshot.
- **Assigned variables**: `asg` is a 64-bit mask of the variables assigned on every way to the current line; `ident` checks it on a read, `capture` and parameters set it. A jump stores it in its `fixs` entry; `label` ands the masks of the jumps seen so far into it (`labasg`) and keeps the result in the entry of the label; a backward jump must contain that mask. After `jmp` and `ret`, `godead` sets all bits until the next label; a label reached only from below starts from `jmask`. `fndef` and `fnend` save and restore the three in `tasg`, `tdead` and `tjmask`.
- **Finding names**: labels, functions and global names go through one hash (`buckets`, `hnodes`; `hfind`, `hadd`), keyed by kind, scope and name; `llab`, `lfn` and `lbuf` wrap it. A table entry needs a node to be found: `globdone` adds the one of a global name when its statement is complete. Each pass over a function has its own `scope` number, the node count is in the function snapshot and `hundo` removes the nodes of the first pass. A jump to a label not yet defined keeps the and of `asg` in a pending node, which `labasg` reads.
- **Labels and jumps**: `label` records the output cursor under its name (table `labs`). `jmp`, `jz` and `jnz` are `optab` rows flagged `IS_JMP` whose bytes stop before the `rel32`; the name after their operands is taken as a label by `jtarget`, which appends the name and the `rel32` address to `fixs`. `resolve` fills in every jump of the current scope, backward ones included, and reports `undefined label`; `fin` calls it for the top level and `end` for a function. Both tables are sized from the source limit and cannot overflow.
- **Blocks**: rows flagged `IS_IF` end before the `rel32` of the opposite jump; at the end of such a statement `arg` pushes the `rel32` address and `asg` on `blks`. `end` with a block open (`nblk` above `blkbase`) goes to `blkend`, which fills in the jump and merges `asg` with the recorded mask; `else` (`elsedef`) emits a `jmp`, retargets the entry and remembers how the first part ended. No label is created. `while` (`whiledef`) forgets `vk`, notes the place of its value in the source (`wsrc`, `whead`) and continues as the statement `if`, whose `blks` entry (40 bytes) takes along the first line of the loop and `wsrc`. `blkend` then checks `asg` against the mask of the head as for a backward jump, adds the loop to `loops` in pass 1, and reads the value again from the source as that of a `jnz` (`wend`, `wip`, back to `arg`); `wclose` writes that test and the jump back to the first line (`wbody`), lets the jump of the head land behind it and restores the cursor and `asg`. A loop thus tests at both ends and a round is one jump. `exname` never moves a last mention back, because of that second reading. **The zero flag**: `xarith` (not `imul`) and `xshift` by a number note the register of their result and the output cursor in `xflg` and `xflgpos`, and `xjcond` leaves out `test reg, reg` when that register is tested with the cursor unmoved (`i-=1` then `jnz i l` is `sub rbx, 1` / `jnz`); `label` and the end of a block forget the note, being the places control reaches without a byte written.
- **Functions**: `fn` emits a `jmp rel32` over the body (patched by `end`), then the entry: one `push` for each of the variable registers the function uses (`fnregs`, counted by `alloc`; `pushlen` gives the bytes), `sub rsp` for the frame if any (a frame of a page or more through the template `probe`, which touches every page), and one `mov` per parameter from its argument register (`rax`, `rdi`, `rsi`, `rdx`, `r10`, `r8`). It saves `nv` and remembers where the function's labels and jumps start (`labbase`, `fixbase`); `end` emits `xor eax, eax` and the epilogue, resolves the function's jumps and cuts `labs` and `fixs` back, which is what makes labels local. `ret` is an `optab` row (`IS_RET`) whose bytes are the six `pop`s and `ret` (also the table `retc`); `popskip` says how many of those bytes to leave out. `tail` has the flags of `call` and `ret` and the bytes of the pops plus `E9`. `call` is a row flagged `IS_CALL`: values after the sixth are loaded into `r11` (row 7 of `regtab` and `argnum`, chosen by `aidx`) and pushed by `anext`, which counts the bytes in `pushed`; `vplace` adds `pushed` to stack-slot distances and `eop` emits `add rsp` after the call. The callee loads those parameters from above its frame, which needs `fnnpar` from the first pass. `next` reads the function name into `cn` and `cl`, and `eop` appends name, `rel32` address and value count to `calls`, which `fin` resolves against `funs`, reporting `undefined function`, `wrong argument count` and `wrong result count` (the results of the function against the names after `as`, which `capture` collects in `caps`). `ref` is a call entry with the count -1 and gets an absolute address; `callp` (`IS_PTR`) puts its first value in `rcx`, row 8 of `regtab`, and is not recorded.
- **Strings and data** are inlined in the code stream behind a `jmp rel32`; a string is addressed by a `lea` whose distance is known at once, so no data section or second pass is needed. The code segment is not writable, so they are read-only. `sbytes` copies the bytes of a literal for both. A `data` statement that starts where the previous one ended (`dataend`) appends to it and rewrites that jump (`datarel`) instead of emitting its own; `label` clears `dataend`, so a label after data stays the address of code. The row flag `IS_LEN` makes an operand its length instead of its address, and `IS_AT` makes the first one (`atname`) two values, address and size; the size of a global name is a `refs` fixup of kind 2, the bytes to the end of its object.

Adding a statement that takes values in `rax`/`rdi` and leaves a result in `rax` means adding a row to `optab` in `stage1/tables.ai`, with a case in `tests/insn.cases`; anything else needs a row with flags 255, its `jeq` in `next` and its own state ending in `eol`. Either way add tests for what it accepts and rejects. The source of the compiler may not use a new statement until a seed that understands it is pinned in `seed/MANIFEST`. Forward references go through a fixup list: `fixs` holds the `rel32` jump displacements to labels of the current scope, `calls` the `rel32` displacements of calls, `refs` every place that `fin` must fill in once the layout is known: kind 0 the `rel32` of an address of a buffer or data name, 1 and 2 the `imm32` of a length (`len`, `at`), 3 the `rel32` of a var cell; `fin` resolves `refs` last and reports `undefined variable` there.

**The read-only tables** (ELF header, statement rows, register tables, syscall names) are `data` lines in `stage1/tables.ai`, which `stage1/ailc.ai` names with `use` in its last line. That file is their definition and is edited by hand, one row a line; a row is decimal bytes, so write the instructions, take their bytes from `tests/insn.sh hex`, and add the case that checks them.
