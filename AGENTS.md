# AGENTS.md

This file provides guidance to AI coding agents when working with code in this repository.

## What this is

AIL is a proof-of-concept programming language whose design goal is low token consumption when an AI writes it. `docs/tokens.md` of the repository ail-bench has the measured cost and what it decides: fewer lines matter more than shorter words, and a number costs more than a name. Write a computation as an expression (`x=a+b*c`, `x+=1`, `store p+8 n/10`, no spaces in it), a test and its consequence as a block (`if a<b`), and a loop as `while`; `tools/infix.aiw` rewrites an existing source that way, and `tools/fuse.aiw` makes blocks out of labels and jumps. It is hardware-oriented (assembly-like, no classes or objects) and human readability is explicitly not a goal. When adding syntax, prefer short common words and bare spaces over punctuation and boilerplate, and let the compiler infer anything derivable (for example, a string literal supplies its own length).

The compiler is written in AIL: `compiler/ailc.aiw`, which holds the declarations and the top level and names the files of its functions with `use`, `compiler/diag.aiw` (errors), `compiler/lex.aiw` (input), `compiler/names.aiw` (tables of names), `compiler/pkg.aiw` (packages), `compiler/expr.aiw` (expressions and their code) and `compiler/emit.aiw` (output), with its tables in `compiler/tables.aiw`. It was translated from a compiler in assembly, stage0, which built it first and was removed on 2026-11-20; the directory `compiler` was called `stage1` until then. Sources have the extension `.aiw`; until 2026-11-20 it was `.ai` and the repository was called `ailang`, names that other technology already had, and until 2026-11-21 it was `.aw`, which GitHub Linguist counts as PHP. The build starts from a seed, a released executable of the compiler that `seed/MANIFEST` pins by version, source revision and SHA-256 (`tools/seed.sh` takes it from `seed/ailc-<version>` or fetches it with `curl` or `gh`), and compiles the source in three generations, `build/ailc1` by the seed, `build/ailc` by that and `build/ailc2` by `build/ailc`; the last two must be the same file. The source of the compiler may therefore use only what the pinned seed understands; since seed 2 that includes expressions, `x=e` and `while`, and the source is written with them; seed 3 also has `spawn`, `join`, `async` and `await`, seed 4 the statements on two doubles (`padd`, `psub`, `pmul`, `pdiv`, `pmadd`), `fsum` and `fdot`, seed 5 those on binary32 (`f4to8`, `f8to4`, `fdot4`), seed 6 takes packages as arguments and reads `use "name:path"`, seed 7 has the statement `rt` and a runtime written in C, and seed 8, pinned since 2026-11-26, has the runtime in AIL; the services the source of the compiler calls are those of the pinned seed.

## Rules

- Sources are indented with one tab for each block (`docs/language.md`, "Source style"); run `build/tools/indent` on a source you write or edit, `make test` checks it.
- All repository text is in English: documentation, code comments, commit messages, test names, compiler messages and the knowledge base. This holds even when the conversation is in another language.
- A commit message is `type: subject` (`feat`, `fix`, `test` or `docs`, no scope, lower case, no full stop) and a prose body wrapped at about 70 columns: the problem, what changed and why, how it was verified. One backlog item or fix is one commit, with its tests and documentation.
- Commit messages and pull request descriptions carry no trailers or attribution lines: no `Co-Authored-By`, no `Signed-off-by`, no "Generated with" footer. This holds even when the tool in use suggests one.

## Measurements

The benchmarks are in a repository of their own, ail-bench (https://github.com/CristianosLeite/ail-bench): the programs in C, Rust and assembly that mirror `examples/`, the algorithm, array and collection programs with their harness, the task and async programs that are timed, the tools `perf`, `par`, `tokens` and `nptime`, the checks of those programs, and the documents `docs/performance.md` and `docs/tokens.md`. It fetches this repository at the revision its file `ail.pin` names, or links to a checkout (`make AIL=<path>` there), and builds the compiler from it; it reads `lib/`, `examples/` and `tools/lib/rng.aiw` from here, so a change of those paths is a change there too. After a change to the compiler or a library that may move time or tokens, run `make test` and the tool in question there, and move the revision in `ail.pin` when this repository is ahead of it. Nothing in `make test` here measures time or counts tokens.

## Commands

Requires x86-64 Linux and the seed: a local `seed/ailc-<version>`, or `curl` or `gh` and network to fetch it once.

```
make            # build build/ailc (from the seed) and every example in examples/
make test       # run every test in tests/, the I/O checks of tests/io.sh and
                # the packages of use (tests/pkg.sh) and the command ail
                # (tests/cli.sh) and an installation of it (tests/install.sh),
                # check a failed example build (tests/make.sh), the form of the
                # tables (tests/tables.sh) and of the runtime (tests/rt.sh),
                # the compiler for Windows under Wine (tests/win.sh), instruction bytes (tests/insn.sh) and
                # emitted files (tests/bytes.sh), compare the compiler with its
                # seed-built translation and check the fixed point (tests/self.sh),
                # fuzz it (tests/fuzz.sh), check the rewriting tool (tests/infix.sh)
                # and the formatter (tests/indent.sh) and the tools
                # written in AIL (tests/tools.sh), replay random programs with
                # the result Python computed (tests/randvars.sh)
                # and run random programs against a computed result
                # (build/tools/randvars); nothing of it needs Python
make tools      # build every tools/<name>.aiw as build/tools/<name>; make test does it too
build/tools/hashcol   # two names in one bucket of the compiler's hash, for tests/hash_collision_prefix
make fuzz N=50000 SEED=3   # a longer fuzz; a source that fails is kept in build/fuzz/
make test T=hello   # run one test
make build/foo  # compile examples/foo.aiw to build/foo
make clean
tests/insn.sh hex 'shr rax, 13'   # the bytes GNU as writes for instructions, for a case in tests/insn.cases
tests/insn.sh asm   # check tests/insn.cases against the assembler
build/tools/fuse in.aiw out.aiw  # rewrite a source with compare-and-jump statements and if blocks
build/tools/infix in.aiw out.aiw  # rewrite statements as expressions, label loops as while, fold temporaries;
                                # run it where the paths of the source's use lines lead, and name after
                                # out.aiw the file that declares the vars of a source it includes
build/tools/indent file.aiw ...  # indent sources in place, one tab a block level; --check lists the lines
                                # that would change and exits 1, - reads stdin and writes stdout
build/tools/randvars build/ailc 2000 1      # more random programs than make test runs:
build/tools/randvars build/ailc 2000 2 top  # run after touching variable allocation
build/tools/randvars build/ailc 2000 3 async  # the same in an async function, with waits
build/tools/randvars build/ailc 2000 4 asyncs # with few waits, so that variables are in registers
build/tools/randvars dump dir 5 1   # write the programs of a seed to dir/<n>.txt, compiling nothing
```

The compiler reads source on stdin and writes the executable on stdout; its only arguments are `name=directory`, each a package whose files a source names as `use "name:path"` (`docs/language.md`, Packages; `tests/pkg.sh` with the sources under `tests/pkg/`). A package has a manifest, `Ailfile`, and AIL has its own, with its version (`docs/packages.md`); `cli/manifest.aiw` reads it. The command `ail` (`docs/cli.md`) is `cli/ail.aiw`, the only file of it that prints and exits, with `cli/tool.aiw`; `make` builds it as `build/ail` and `tests/cli.sh` runs it on packages it makes. `ail test` runs the tests of a package by the convention of `tests/run.sh` below, and `ail fmt` its formatter. `ail build --target windows-x86_64` and `ail test --target windows-x86_64` do both for Windows, with the compiler `ailc-windows-x86_64` beside `ailc`, into `build/windows-x86_64/`: the tests are run by `wine`, but for those that `tests/windows-x86_64.skip` of the package names, and `tests/win.sh` does it with a package it makes (`win_package`). `cli/deps.aiw` finds the packages a manifest names and fetches those from a git repository into `deps/` at the revision of `Ailfile.lock`; `ail add`, `remove` and `update` change the manifest. `tests/cli.sh` tests them against repositories it makes, with no network. `make install PREFIX=<dir>` and `make dist` put the command, the compiler, the compiler for Windows, the formatter and the library in one place (`tools/install.sh`, `tests/install.sh`). A `use "path"` in the source is opened relative to the directory the compiler runs in, so run it from the top of the repository for sources that use repository paths (the compiler's own source and the tests do):

```
build/ailc < prog.aiw > prog && chmod +x prog
```

Files that tests name with `use` are in `tests/lib/`. A test is a set of files `tests/<name>.*`, run by `tests/run.sh` (with the compiler named by `AILC`, default `build/ailc`):

- `.aiw`: the program, or `.aiw.sh`, a script that prints it (used for generated sources such as the size-limit tests)
- `.out`: expected stdout of the compiled program
- `.code`: expected exit status of the compiled program, default 0
- `.err`: expected compiler stderr; the compiler must then exit 1

A test has either `.err` (compiling must fail) or `.out` (the program must run). The runner kills a compiler or a program after 10 seconds, with `SIGKILL` to its whole process group, and fails the test, so a loop that never ends cannot hang the suite or outlive it. The compiler's I/O errors do not fit that form and are checked by `tests/io.sh`, which `make test` runs after the suite when no `T` is given: closed stdin, memory that the kernel refuses, output to `/dev/full`, output to a pipe whose reader is gone, and a short write (a non-blocking pipe that takes 4096 bytes: the compiler must write that prefix, then report the error). `make test` names the compiler of every run itself, so an `AILC` in its environment changes nothing. `build/ailc1` and `build/ailc` are the same source in two translations, by the seed and by the compiler the seed built, so they must behave alike: `tests/self.sh` gives the source of every test and example to both and requires the same stdout, stderr and exit status, then requires `build/ailc` and `build/ailc2` (the source compiled by `build/ailc`) to be the same file. That comparison is trivial while the seed is the current compiler and is the check of self-compilation once the compiler writes other code than the seed. `tests/fuzz.sh` gives both sources made by random edits of the tests, examples and libraries (300 in `make test`, from a fixed seed; it never runs what it compiles) and requires, besides the same behaviour, that the compiler ends properly: status 0 with an executable and no message, or status 1 with one `ailc: ` line and no output. `tools/randvars.aiw` builds random programs of arithmetic with every operator, loops and blocks with an `else`, writes each one three times from the same tree, with statements, labels and jumps, line for line the same with each statement spelled as an expression, and with nested expressions, `x+=e`, `while` and `if` on a comparison, computes the exit status all must give by running the tree in a function that shares nothing with those that write, requires the first two to compile to the same bytes, and runs them with a limit of 10 seconds, 200 in a function, 200 at top level, 200 in an async function that waits before every third statement and 200 in one that waits before every twelfth (`asyncs`), which leaves variables that no wait falls into, in registers; a program that fails is kept in `build/randvars/`. Its random numbers are splitmix64 (`tools/lib/rng.aiw`), so a seed gives the same programs everywhere. The tool is compiled by the compiler it checks, so `tests/randvars.sh` also replays 20 programs in `tests/randvars/` that the Python script wrote which the tool was ported from, with the status Python computed, requires the tool to write the program of `tests/randvars/dump/0.txt` for the seed 1, and checks what it reports for a compiler that fails. `tests/insn.sh` and `tests/bytes.sh` are the checks that do not take a compiler's word for the output. `tests/insn.sh` compiles each source of `tests/insn.cases` and requires the code between the runtime and the end of the program to be the hex beside it, which GNU `as` wrote from the instructions in the third column; there is a case for every row of the statement table and for the other tables, and a new or changed row needs one. `tests/tables.sh` checks the form of `compiler/tables.aiw`: lengths, names that occur once, flags, table sizes, and the syscall numbers against a list of its own. `tests/bytes.sh` looks at whole files: for six programs that fill a fixup table to its capacity it computes the expected file in awk, the header and the code of the program with every displacement, taking where the runtime ends from the empty program, and compares; the seed-built translation must then give the same file. `tests/infix.sh` checks `tools/infix.aiw` on the fixture `tests/infix/in.aiw`: it must give `tests/infix/out.aiw`, leave that unchanged when run again, and both must be the same program; `tests/infix/long.aiw`, two assignments in place too long for one line, must stay the program it is, and `tests/infix/edge.aiw` (separators, CR, comments, the limit of 100 bytes) must become `tests/infix/edge.out.aiw`; `tests/infix/use.aiw`, which sets a `var` of the file it names with `use`, and `tests/infix/part.aiw`, whose `var` is in a file named on the command line, must stay as they are. The expected files are what the Python script wrote that the tool was ported from, indented since by `build/tools/indent`, which changed no other byte; the fixture indented first must give the same, and a result must pass `indent --check`. `tests/indent.sh` checks `tools/indent.aiw`: a copy of `tests/indent/in.aiw` must become `tests/indent/out.aiw` and that stay as it is, both compiling to the same bytes; `tests/indent/wrong.aiw`, which is no program, must become `tests/indent/wrong.out.aiw`; `--check` must list the lines that would change and write nothing, `-` must filter stdin, and a file that cannot be read or written is reported; last it runs `--check` on every source of `examples/`, `compiler/`, `lib/`, `tools/` and on the tests, so a new or edited source must be indented (`build/tools/indent file.aiw`). The files listed in `tests/indent/skip`, the tests of the separators, and the fixtures in the directories under `tests/` are not indented. `tests/async_idle` checks that a program with the whole runtime compiled in and no task leaves every buffer of it zero and opens no descriptor. `tests/make.sh` runs `make` in a scratch copy to check what the Makefile does when an example fails to compile: the build fails each time it is tried, an executable from an earlier build stays as it was, and no temporary file is left; the same for a tool. `tests/tools.sh` checks the tools written in AIL: the prerequisites the Makefile gives each `build/tools/<name>` must be its source and every file that source reaches with `use`, `hashcol` must print the two names that `tests/hash_collision_prefix` declares, `ndgen` must write `tests/lib/ndfix.aiw` and refuse an argument, and `fuse` must make `tests/fuse/out.aiw` of `tests/fuse/in.aiw` (what the Python tool it was ported from made of it, indented) and of that source indented, leave that and `tests/fuse/same.aiw` unchanged, keep the program what it was and refuse missing arguments, an unreadable file and a label without a name. Without the pinned files it prints `skip` and succeeds, so `make test` needs no network.

Compiler errors are one line on stderr, `ailc: <place>: <message> <name>`, where the place is the line number, with `<path>:` in front for a line of a file named by `use`, and the name is given for the messages about one. The messages are `syntax error`, the more specific `unknown statement`, `not allowed here`, `missing end`, `missing as`, `unexpected as`, `missing label`, `wrong operand count`, `unterminated string` and `expected a name`, and `undefined variable`, `unassigned variable`, `too many variables`, `duplicate name`, `invalid access`, `number too big`, `buffers too big`, `undefined label`, `undefined function`, `wrong argument count`, `wrong result count` and `cannot read file`, all with exit status 1. `source too big` and `program too big` (status 1) and `read error`, `write error` and `no memory` (status 2) have no place. `docs/language.md` has the table of causes; a test's `.err` file holds the whole line.

A pull request to `main` runs `make test` on GitHub (`.github/workflows/test.yml`), on a runner that fetches the seed from its release; nothing else starts it, no push and no schedule.

## Tools

A tool written in AIL is `tools/<name>.aiw`, compiled by `build/ailc` after the bootstrap to `build/tools/<name>` (`make tools`; the compiler needs none of them). The entry point handles arguments, messages and the exit status. The files it names with `use` are prerequisites in its line of the Makefile, which `tests/tools.sh` compares with the `use` statements, so a new `use` needs the file added there. What several tools need is in `tools/lib/`: `scan.aiw` (prefix `sc`: classes of bytes, string literals, and a table that gives every word a number, so that tools compare and look up words as numbers) and `flow.aiw` (prefix `fw`: `fwscopes`, the lines of each function and of the top level, and `fwdead`, the walk that says whether a value is dead, which asks the tool about each line through a function passed by `ref`). `rng.aiw` (prefix `rng`) is splitmix64 with its state in 8 bytes of the caller: `rngseed`, `rngnext`, `rngbelow`, which is unbiased, and `rngshuffle`; its test is `tests/lib_rng`. No tool is written in Python any more; `tools/` has the shell script `seed.sh` besides. The tools that measure (`perf`, `par`, `tokens` with its tokenizer, `nptime`) and `tools/lib/fmt.aiw` are in the repository ail-bench. `indent` sets the indentation that `docs/language.md` describes under "Source style" and changes no other byte: a depth counted from the first word of each line (`dtkind`: a word that opens a block, `else` or `end`, only when a blank, a comment or the end of the line follows, so `if=1` is an assignment), with the lines inside a string that spans lines left alone (`dtstrend`; `dtafter` is the same for a line that starts outside a string, and says that a `use` never leaves one open, since its path has no escapes; `fuse` reads its lines with both); the walk is `dtindent` of `tools/lib/dent.aiw` (prefix `dt`, with `dtkind` and `dtstrend`), which writes into a buffer and calls a function for each line that changes. `fuse` and `infix` pass what they made through it, so their results are indented: `fuse` reads each line without the blanks before it, and `infix` measures the column of a comment from the first word. The VS Code extension for `.aiw` files is in the repository ail-extensions (https://github.com/CristianosLeite/ail-extensions, `editors/vscode/` there) since 2026-11-21; its folding repeats `dtkind` and `dtstrend`, and its check (`make check` there) requires each statement of `compiler/tables.aiw` to be coloured as one and the folds to be the blocks `build/tools/indent` indents, against this repository at the revision its `ail.pin` names. A new block statement is added to `tools/lib/dent.aiw` here and to the extension there, and the check is run there after a new statement. `fuse` and `infix` each keep their own reading of a line, their rules and, in `infix`, the expression trees and their printer. `infix` folds no name that a `var` declares, and reads the `var` lines of every file the source reaches with `use` and of the files named after its two arguments (`declfile`). A tool keeps its state in `var`s named with a `g` in front and its variables off those names; text is an address and a length, and a place in a buffer that may grow is an offset.

## Library

`lib/std/task.aiw` holds the functions `spawn` and `join`, `workers` (the limit of the pool) and the pool of threads that runs tasks: a queue under a lock in the buffer `taskq` that sleeps in `rt wait`, workers started by `rt thread` on demand up to the limit and kept, and a `join` that runs a task nobody took. It has no top-level code and no `var` (a `var` name is written by `as` in any function of the program); its tests are the `spawn_*`, `join_*` and `task_*` files. `lib/std/io.aiw` is AIL code that programs compile in with `use "lib/std/io.aiw"`: `print`, `eprint`, `fdwrite`, `die`, `putn`, `strlen`, `argc` and `argv`. Its tests are the `lib_io_*` files in `tests/`. A new helper goes there only if several programs need it. `lib/std/bytes.aiw` (prefix `by`) is a buffer of bytes that grows: 24 bytes owned by the caller (address, length, room; all zero is empty), `byneed`, `byadd`, `byaddb`, `byaddn`, which may move the bytes and return 0 without memory, `bycopy`, `bycut` and `byfree`. `lib/std/file.aiw` (prefix `file`, needs `lib/std/bytes.aiw`) reads and writes whole files, through the runtime alone: `fileread` and `filereadfd` add to such a buffer, `filewrite` replaces a file, `fileopen` gives a descriptor; a path is an address and a length, a negative result is the error of the runtime. `filemkdir`, `fileunlink` and `filermdir` take a path the same way, and `filenames` adds the names in a directory to a buffer. `lib/std/proc.aiw` (prefix `proc`, needs `lib/std/io.aiw`) runs child processes, through the runtime alone: `procstart` with an argument vector and the three descriptors of the child and `procheld`, a child that ends with the process that started it (`rt start`, whose flag 2, a child that leads a group which ends with it and with its starter, `cli/tool.aiw` uses for a test: on Linux `fork`, `dup2` in an order that overwrites no descriptor still to be read, with a copy only for two that are each other's, after checking that all are open, `execve`, with a search of `PATH`), `procwait` with a limit in milliseconds (`rt reap`: the status, a negated signal, -1000 after killing a child that ran too long), `procenv` and `procvar`, `procnow` (`rt clock`, the monotonic clock in nanoseconds) and `procpin` (`rt pin`, bind the process to one CPU). No file of `lib/`, `cli/` or `tools/` has a `sys`, which `tests/rt.sh` holds, with the form of the image and its place in an executable. Their tests are the `lib_bytes_*`, `lib_file_*` and `lib_proc_*` files. `lib/std/vec.aiw` (prefix `vec`) is a vector of 64-bit values that grows: 24 bytes owned by the caller (address, length, room in values; all zero is empty), `vecpush`, which doubles the room (at least 512 values), and `vecreserve`, which takes the room it is asked for in all; both may move the values and return 0 without memory or for room whose bytes do not fit, leaving the vector as it was; `vecpop` and `vecget` return a value and 1, or 0 and 0, `vecset` 1 or 0, and `vecfree` leaves the 24 bytes zero. Its tests are the `lib_vec_*` files. `lib/std/queue.aiw` (prefix `queue`) is a queue of 64-bit values with a fixed room, a ring: 32 bytes owned by the caller (address, room, index of the oldest, count), `queueinit` with one `alloc`, `queuepush`, which returns 0 when it is full, `queuepop`, a value and 1 or 0 and 0, and `queuefree`; a queue that is all zero is full and empty. Its tests are the `lib_queue_*` files. `lib/std/heap.aiw` (prefix `heap`, needs `lib/std/vec.aiw`) is a heap that gives the smallest value first, in the unsigned order: a vector whose value at `i` is not larger than those at `2i+1` and `2i+2`; `heappush` (a `vecpush` and a move up through a hole), `heappeek` and `heappop` (a value and 1, or 0 and 0), `heapfree`. Its tests are the `lib_heap_*` files. `lib/std/map.aiw` (prefix `map`) is a hash map from 64-bit keys to 64-bit values with open addressing and linear probing: 32 bytes owned by the caller (address of the table, places, keys, places that hold or held a key), places of 24 bytes (0 free, 1 a key, 2 taken out; key; value) in a power of two, at least 64; `mapput`, which returns 0 without memory and at three quarters of places used moves the keys to a new table (`mapgrow`: twice the places if the keys fill half, else as many) that it publishes when it is whole, `mapget` (a value and 1, or 0 and 0), `mapdel`, which leaves a mark that a later key reuses, and `mapfree`; `mapfind` is the one walk all of them use. Its tests are the `lib_map_*` files. `lib/std/num.aiw` (prefix `num`) reads numbers from decimal text: `numint`, a signed whole number and 1, or 0 and 0, and `numdouble`, the binary64 nearest to a number as JSON and C write one, a tie to the even one, whatever the number of digits (at most 15 digits and a power of ten up to 22 by one exact operation; else a rough double moved to the nearest by comparing whole numbers of 32-bit limbs, `nummul`, `numfive`, `numshl`, `numcmp`, in its frame). Its tests are the `lib_num_*` files; `lib_num_double.out` is what Python computes for the same texts. `lib/std/sha.aiw` (prefix `sha`, needs `lib/std/bytes.aiw` for `shahex` alone) is SHA-256: `sha256` of bytes given at once, `shainit`, `shaadd` and `shaend` for bytes given in pieces, with the sum in progress in `shasize` bytes of the caller (the state, a block that is not full, two counts), and `shahex`, the 32 bytes as 64 digits added to a bytes buffer; it allocates nothing. Its test is `lib_sha_sums`, whose `.out` is what `hashlib` of Python computes. `lib/std/json.aiw` (prefix `json`, needs `lib/std/bytes.aiw`) reads JSON in place, with no tree and no allocation: a value is an address, a length and a kind (1 `null`, 2 `false`, 3 `true`, 4 number, 5 string, 6 array, 7 object, 0 none). `jsonvalue` checks that bytes are one value (`jsonany`, which calls itself up to 128 deep, with `jsonstring`, `jsonnumber`, `jsonutf`, `jsonhex`), RFC 8259 and, as I-JSON, well-formed UTF-8 and whole surrogate pairs; `jsonelem` and `jsonmember` give the elements and members one after the other, `jsonget` the member of a name, `jsoneq` compares a string with bytes and `jsonstr` adds what a string says to a bytes buffer; `jsonadds` and `jsonaddi` write a string and a whole number. Its tests are the `lib_json_*` files. `lib/net/http.aiw` (prefix `http`, needs `lib/std/bytes.aiw` and the three files of `lib/async/`) is HTTP/1.1 over the sockets of `lib/async/io.aiw`: `httphead`, `httpfield`, `httpstatus`, `httpip` and `httpurl` take a message apart, the async functions `httpmore` and `httpbody` read bytes and a body (a length, chunks put together in place, or up to the end of the connection) into a bytes buffer, and `httpcall` sends the request of 128 bytes that the caller owns and reads the response, with a limit of time for each step and of bytes for the whole; one connection a request, no TLS, an address that is a number. `lib/net/httpd.aiw` (prefix `httpd`) is the server: `httpdserve` accepts connections and makes a task, `httpdconn`, for each, which reads a request, calls the handler of the program, an async function, through `callp` with a request of 136 bytes, and writes the response. A carriage return in a string of these files is `\x0d`: the language has no `\r`. Their tests are the `lib_http_*` and `lib_httpd_*` files, each against a server or a client of its own on 127.0.0.1 with a port the kernel chose; `lib_http_no_memory` and `lib_httpd_no_memory` limit the memory of the process, as `lib_map_no_memory` does, and take every record of an event, so that a request has no room, a connect or an accept cannot be made, and a connection is cancelled while its handler waits. The four collections have caller-owned descriptors that are empty when all zero, check a size before they multiply it, change a descriptor only after `alloc` succeeded, and return a second result where 0 is a value; `tests/lib_vec_no_memory` and `tests/lib_map_no_memory` limit the memory of the process with `setrlimit` and require the call that is refused to leave every value. The files of `lib/algo/` are the kernels of the algorithm programs of the repository ail-bench (`bench/<name>.aiw` there), which only call them: `sort.aiw` (prefix `sort`: `sortquick` from an address up to another, `sortmerge` with a work array, `sortheap` with `sortsift`, `sortins`), `search.aiw` (`searchlower`, the first index whose word is not smaller than a key), `hash.aiw` (prefix `hash`: a table of a fixed size in bytes of the caller, 16 bytes a place, the key 0 a free place; `hashplace`, `hashfill`, `hashfind`) and `graph.aiw` (`graphbfs`, `graphdfs` over two arrays of offsets and neighbours). They are on words of the caller in the unsigned order, allocate nothing and return no error; each file has its own prefix because the harness of those programs owns `algo`. A function called in a loop stands before its caller in the file (`hashplace`, `sortsift`, and `searchlower` before the program that uses the file), so that it is compiled in place. `sortheap` and the table are apart from `lib/std/heap.aiw` and `lib/std/map.aiw`, whose layouts are others. Their tests are the `lib_algo_*` files. `lib/nd/array.aiw` (prefix `nd`) is arrays of doubles with a shape, on the model of NumPy: 176 bytes owned by the caller (address of the element at index 0, kind of the elements, 1 at first, number of axes up to 8, address and bytes of the storage, whether the array owns it, 8 lengths, 8 signed strides in bytes; all zero is no array), `ndnew` (storage of its own, zeros; `ndvec` and `ndmat` for one and two axes) and `ndwrap` (bytes of the caller), which lay the elements one behind the other, the last index fastest, refuse an axis or a count of 2^60 or more (`ndcount`) and write the array only when all went well (`ndmake`), `ndfree`, `ndsize`, and `ndat`, `ndget` and `ndset`, which take the indices as words at an address and check each. Views are 176 bytes over the storage of another array, never owning it unless they are written in its place: `ndslice` (one axis, from an index up to another, with a signed step), `ndtrans`, `ndswap`, and `ndreshape`, which needs `ndcontig`; `ndcopy` gives any array storage of its own. Every function goes over elements with a walk (`ndwalk`, `ndwarg`, `ndstep`): 384 bytes in a `local` with the lengths of the result, the indices of all axes but the last, and for up to three arrays the address of the current run along the last axis and their strides, 0 where an array has no such axis or one of length 1; `ndfill` and `ndcopy` use it. `ndspan` gives the lowest address of an element and the one behind the highest, and `ndvalid` says whether they lie in the storage. `lib/nd/elem.aiw` (needs `lib/nd/array.aiw`) has `ndadd`, `ndsub`, `ndmul`, `nddiv` and `ndput`, result first, which all are `ndelem` with a number for the operation: the result is an array of the caller and its lengths are those of the walk, the two others are given to `ndwarg`, which broadcasts or refuses; the result may be one of them when `ndsame` says so, any other meeting of their `ndspan`s is refused (`ndclash`), as is a result with a stride of 0 on an axis longer than 1; when the result and both others lie one behind the other or have one element (`ndflat`) the walk is made one run, and `ndrun` computes a run: when the stride of the result is 8 with a loop for each operation that has an end and, for each of the two others, a distance to the result (stride 8) or its one element read before the loop (stride 0), otherwise with a loop that has the three strides and chooses the operation for each element; a run whose result has the stride -8 and whose two others have it too or 0 is first turned round, to its lowest address and the stride 8 (`tests/lib_nd_reversed`). Before all of that `ndelem` takes a short way for the four operations on doubles: a result of one axis and stride 8 that is not empty, two others that `ndlike` finds like it or without axes, and addresses apart from the result's, give one call of `ndrun` and no walk (`tests/lib_nd_short`). `ndscalar` is an array without axes with its element at 48 of its own 176 bytes. `lib/nd/reduce.aiw` (needs both) has `ndsum`, `ndmean` and `ndsumpw` (a number and 1, or 0 and 0; `ndtotal` walks, `ndacc` adds a run one element after the other from a start, doubles with `fsum`, `ndpair` in halves down to 128 elements, a run of doubles that lie one behind the other two at a time into sixteen sums, `ndpack`, so `ndsumpw` promises no order within a run) and `ndsumax` and `ndmeanax`, result first: the result gets an axis of length 1 where the array has the one to sum over, in a copy of its 176 bytes, and is then the second array of a walk over the array, so that its address stays for a run or for a column; a sum starts from 0 and adds in the order of the indices, the sum of nothing is 0 and its mean no number. `nddot` (two arrays of one axis) and `ndmatmul` (result first, three arrays of two axes, the result apart from both others and with every element at its own address, which `ndmmok` checks through the strides, multiples of 8, divided by what divides both; `tests/lib_nd_matmul_alias`) are in the same file: the product zeroes the result and adds, for each row `i` and each `k`, the element `i`, `k` times row `k` of the second matrix to row `i` of the result (`ndaxpy`), so every element is summed in the order of `k`; `nddot` of doubles that lie one behind the other is an `fdot`. The kind at 8 of an array is 1 for doubles and 2 for integers with a sign, set by `ndkind` without touching a bit: the arrays of one call are of one kind, but for `ndtoi` and `ndtof` (operations 5 and 6 of `ndelem`) and for the means, which are doubles of the elements as `itof` gives them. Integers are the operations 8 to 11 of `ndrun` and a mode of `ndacc`, `ndpair` and `ndaxpy`: they wrap at 64 bits, a divisor with a 0 (`ndhas0`) is refused before anything is written, and the lowest integer by -1 stays what it is. `ndmatmul` is `ndmmok`, which checks, a fill with zeros and `ndrows`, which adds the rows from one index up to another; `lib/nd/par.aiw` (needs `lib/std/task.aiw` and the three files) has `ndmatmulp`, which after the same check spawns `ndrows` for up to 64 runs of rows (`ndruns`: the rows divided by the tasks, rounded up, so there may be fewer runs than tasks asked for), keeps the handles in a `local`, computes a run itself when `spawn` gives 0, and joins them all: disjoint rows, the same bits (`tests/lib_nd_matmul_tasks`). Where doubles lie one behind the other and each element of the result is computed alone, the loops take two at a time with `padd`, `psub`, `pmul`, `pdiv` and `pmadd` and the last of an odd count alone: the loops of `ndrun` for a result of stride 8 (a number that goes with all in 16 bytes of a `local`, twice), the sums of `ndaxis` along another axis than the last, and `ndaxpy`, which takes four `pmadd` a round while eight doubles are left (`tests/lib_nd_matmul_wide`); `tests/lib_nd_pairs` requires the bits of the same arrays taken backwards, which go one at a time. Its tests are the `lib_nd_*` files. `tests/lib/ndshow.aiw` prints an array for them (`show`, `showx`, `showi` for integers) and fills one (`ramp`, `count`). The tests `lib_nd_ref_*` compare the library with NumPy without running it: `tests/lib/ndfix.aiw` is `data` lines, 8 bytes a number, of inputs and of what NumPy 2.3.5 computed of them, written by `build/tools/ndgen` (`tools/ndgen.aiw`, no arguments, the file on stdout; `tests/tools.sh` requires its output to be the file), which until 2026-11-22 was a Python script that ran NumPy and now writes the same bytes without it: NumPy's generator (`default_rng(20261121)`: SeedSequence, PCG64, `uniform`, `integers`), and every result in the order NumPy adds, the pairwise sum (`pw`: 8 sums, blocks of 128) along the last axis, row after row along another, a product in the order of the middle index, by kernels on plain addresses that share nothing with `lib/nd` (a view or a broadcast is copied out first, `take`), and `tests/lib/ndcheck.aiw` wraps such data as an array (`fix`) and counts the elements that differ (`differ`: the same bits for the arithmetic and for integers, within 2^-40 of the sizes for sums and products, whose order of adding is not NumPy's (`near`, which takes no difference that is not finite for near; `tests/lib_nd_near`), and the same bits or both no number for the special values). A new kernel gets its case in `tools/ndgen.aiw` and the file is written again (`build/tools/ndgen > tests/lib/ndfix.aiw`); such a case is what the tool computes in NumPy's order, no longer what NumPy computed. `lib/async/task.aiw` (prefix `async`) runs tasks that are polled, on one thread: a task is a record of 64 bytes (poll function, a cell for the place to go on, result, state, queue link, the task that awaits it, the one it awaits, a cancel function) with its values behind; `async` makes one and queues it, `await` gives a result and 1 or registers the asking task and gives 0 and 0, or with no asking task polls until the result is there, `asyncwake` queues a task once however often it is called and also during its poll, `asyncfinish` ends an event (a task without a poll function), `asyncstep` and `asyncrun` poll, `asyncyield` is a task done at its first poll, `asyncdetach` releases a task at its end without an `await`. Records come from free lists by size class. A record that waits somewhere is armed (`asyncarm`, `asyncdisarm`): a function at 56 that takes it out, and a place in a list through its cells 112 and 120, so such a record is 128 bytes. `asynccancel` ends an armed record or an event with -125, unless the function at 56 returns non-zero, which refuses: `asyncjoboff` does for work a worker has begun (the cell at 72 of the work's record, set with `cas` by the worker and by cancel), and the event then ends with -125 in `asyncdrain`; a task that is told, a limit (`asynclimstop`, the cell at 80 of the limit) and `asyncstop` (bit 128 marks what it has cancelled) wait for such a record, so memory given to the work outlives it; a task it only marks and wakes. `await` gives a marked task a result that is there; at an await that would wait it cancels what was asked for and, unless that ends at once, keeps the task waiting for it, with the handle plus 1 in the cell at 48 of the task; when it has ended the task is told once, with -125, or ended if it was told before (bits 8 and 64 of the state). `asyncstop` cancels the whole list, sets the cell at 136, which makes every task count as marked, polls, and calls the function at 144 (`asyncioend`, `asyncplend`) that gives back descriptors and tables. The thread waits for the outside world through two cells of `asyncq`: the function at 24 (`asynctick` of `lib/async/time.aiw`), called by `asyncstep` when the queue is empty and every 61st poll, and the function at 104 that it sleeps in (`asyncpoll` of `lib/async/io.aiw`), with the count at 112 of what is expected besides timers. `lib/async/time.aiw` has the timers, a heap of deadlines whose events keep their index (`asyncsleep`, `asynctimeout`, a task that takes the first of an event and a timer, `asyncclock`). `lib/async/io.aiw` has the descriptors: a record per descriptor with a generation, watched once by a poller of the runtime (`rt poller`, `rt watch`, on Linux `epoll`, edge-triggered), and two lists of waiting events; an operation (`asyncread`, `asyncwrite`, `asyncwriteall`, `asyncaccept`, `asyncconnect`) is an event that asks the kernel first (`asynctry`) and waits only after `EAGAIN`; `asynclisten`, `asyncport` and `asyncclose` return at once; `asyncclose` takes the descriptor out of the poller before it closes it, since a copy of the descriptor would keep the registration. Every write goes through `asyncput`, which keeps `SIGPIPE` away: `rt send` for a socket, `rt writeq` for a pipe, which blocks the signal around the write and takes it back (bit 1 of the cell at 16 of the descriptor's record says that it is no socket). The file has no `sys`: sockets, the poller and its events (16 bytes: what, tag) are services. `lib/async/pool.aiw` (needs `lib/std/task.aiw` and the three files) has `asyncblock`, an event for a function run by the pool of `spawn`: a worker runs `asyncjob`, which puts its record at the head of a list with `cas` and calls `rt wakeup` on a waker of the runtime (on Linux an `eventfd`) if the polling thread sleeps (`asyncpl+8`, set with `xadd` before the list is looked at again); `asyncpsleep` takes the place of `asyncpoll` in the cell at 104 and ends the events of the list (`asyncdrain`). `lib/async/chan.aiw` (needs only `lib/async/task.aiw`) has bounded channels, a ring of values with a list of waiting sends and one of waiting receives, whose events are armed (`asyncchan`, `asyncsend`, `asyncrecv`, `asyncshut`, `asyncchanfree`), and `asyncfirst` and `asyncany`, a task that every handle of an array in its record wakes and whose result is the index of the first that is done. A program uses the files in that order. No file of it has top-level code; its tests are the `async_*` files. Every variable and parameter of a library starts with its prefix, and a library returns an error instead of ending the program.

## Language

`docs/language.md` is the language reference and `docs/compiler.md` explains the compiler; keep them in sync with the source in `compiler/`. Statements:

- `use "path"`: compiles another file at this place, once per path as written; top level only. All files together share the source limit.

- `sys n a b ...`: raw Linux syscall, up to 6 arguments; `n` is a number, a `const`, or one of the built-in syscall names (`read`, `write`, `open`, `close`, `mmap`, `exit`, ...; the list is in `docs/language.md`), which are names only in that place.
- `rt name a b ... as x y`: a service of the runtime by its name (`exit`, `args`, `alloc`, `free`, `open`, `close`, `read`, `write`, `pipeerr`, `mkdir`, `unlink`, `rmdir`, `rename`, `names`, `clock`, `sleep`, `wait`, `wake`, `cpus`, `thread`, `poller`, `watch`, `unwatch`, `poll`, `waker`, `wakeup`, `listen`, `accept`, `socket`, `connect`, `sockerr`, `port`, `send`, `writeq`, `start`, `reap`, `pin`, `cwd`, `chdir`, `real`, `self`, `kind`, `chmod`, `pid`, `lock`, `become`; the table is in `docs/language.md`), values as for `call`, a string two of them, counts checked; an error is a negative result above -4096. `sys` is for what only x86-64 Linux has.
- `args as p`: the address of argc, the argument addresses and the environment; a service of the runtime, so allowed in a function too.
- `x=e` keeps the expression `e` in `x` as `set e as x` does, and `x+=e`, with any of `* / % + - << >> & ^ |` before the `=`, changes `x` in place by the whole of `e`. One word, no space; the name is read before statements are looked up, so it may be a keyword.
- `set a as x`, and `add sub mul div mod and or xor shl shr` as `op a b as x`: 64-bit, wrapping, unsigned division and shift.
- `eq ne lt le gt ge` as `op a b as x`: 64-bit comparison, unsigned order, result `1` or `0`.
- `fadd fsub fmul fdiv fsqrt`, `itof ftoi`, `flt fle feq`: the same values read as IEEE doubles. A float literal (`1.5`, `-0.25`, `2.5e-3`: digits, a dot, digits, an exponent or none) is the bits of the nearest double and stands wherever an integer does.
- `f4to8 a as x`, `f8to4 a as x`: the binary32 in the low 32 bits of `a` as a double (exact, a signalling NaN made quiet), and the double `a` rounded to the nearest binary32, ties to even, in the low 32 bits with zeros above. Rows of `optab` with one operand, `cvtss2sd` and `cvtsd2ss` on `xmm0`. There is no arithmetic on a binary32.
- `padd psub pmul pdiv` as `op p q r`: the two doubles at the address `p` become the sums, differences, products, quotients of the two at `q` and the two at `r`; `pmadd p q r` adds the two products to those at `p`. No `as`; unaligned, unchecked, both read before the write, the same bits as the statements on one double. They are plain rows of `optab` with three operands and the flag `AS_NONE`, SSE2 between memory and `xmm0`/`xmm1`.
- `fsum a p n s as x`, `fdot a p q n as x`: `a` plus the `n` doubles from the address `p` on, `s` bytes apart, added one after the other, and `a` plus the products of the `n` doubles at `p` with those at `q`, 8 bytes apart, each rounded and then added; the bits of the loop of `fadd` (and `fmul`), with the sum in `xmm0` for the whole run. Rows of `optab` with four operands whose code is a loop.
- `fdot4 a p q n as x`: `fdot` with the `n` elements at `p` kept as binary32, 4 bytes apart, each made a double (`movss`, then `cvtss2sd` between registers) and multiplied by the double at `q`; the bits of the loop of `load4`, `f4to8`, `fmul` and `fadd`. A row of `optab` like `fdot`.
- `xadd p v as x`, `cas p old new as x`: atomic add (old value) and compare-and-swap (1 if stored) on the 64 bits at `p`.
- `sdiv smod sar` and `slt sle sgt sge`: the signed forms of `div mod shr` and of the four orderings. Nothing is checked: overflow wraps, a zero divisor is `SIGFPE`.
- `buf name size`: reserves zero-filled writable bytes (rounded up to 8); the name is a constant address. The size is a number or a `const` and may be 0.
- `local name size`: bytes in the frame of the function it stands in, not zero-filled, gone at return; the name is one of the function's variables but cannot be assigned.
- `ccall f a n as x`: a call of the function at `f` by the C convention of the platform, with `n` values of 8 bytes at the address `a` (six are passed on x86-64 Linux whatever `n` is) and the stack at a multiple of 16; `base as p`: the address the executable is loaded at. For the runtime, which calls code that is not AIL.
- `zero p n`: the `n` bytes at `p` become zero (`rep stosb`), no `as`; `stack p` stores the stack pointer at `p`, top level only, for the first line of the runtime.
- `alloc n as p`, `free p`: run-time storage, services of the runtime: blocks of 39 sizes up to 32 KiB cut from chunks and used again when freed, a larger one a mapping of its own, 16 bytes in front of each; zero-filled, 16-byte aligned, `p` is 0 if the kernel refuses; safe among the threads of the runtime.
- `var a b c`: global 64-bit cells, zero at start, read as a value and written by `as`, visible in every function.
- `const name number`: a named number, usable as any value, as the `sys` number and as a `buf` size.
- `data name item ...`: read-only bytes from strings and byte values 0 to 255; the name is a constant address and is optional. Consecutive `data` lines are contiguous, so a table is one row a line. No limit on their number.
- `len x as n`: the length in bytes of a buffer (as declared), of a data name (its own line) or of a string.
- `at name i n as p`: the address `name + i`, with a run-time trap (`ud2`) unless `n` bytes from there lie inside the buffer, data run or local `name`.
- `load p as x`, `store p a`: 64-bit access at address `p`; `load4`/`store4`, `load2`/`store2` and `loadb`/`storeb` are the 32-bit, 16-bit and byte forms, loads zero-extended.
- `label name`, `jmp name`, `jz a name`, `jnz a name`: a label, and jumps to one always, if `a` is zero or if it is not (all 64 bits); labels may be used before they are defined.
- `jeq jne jlt jle jgt jge` and signed `jslt jsle jsgt jsge` as `op a b name`: compare and jump in one statement.
- `if a`, `ifz a` (where `a` may be a comparison, `if a<b`, at the cost of `iflt a b`), `ifeq a b` and the other comparisons with the prefix `if`, then lines, an optional `else` and lines, then `end`: a block. `end` closes the innermost open block, and the function only when none is open.
- `while a`, then lines, then `end`: a loop that runs while `a` (one value, usually an expression such as `i<n`) is not zero, tested before each round. A block like `if`, without `else`; after it only what was assigned before it is assigned.
- `fn name a b` ... `end`: a function with up to 64 parameters; top-level execution skips the body, functions do not nest, and reaching `end` returns 0. `ret a b` returns one to six values, the same number at every `ret` of the function, and is only allowed inside a function.
- `async fn name a b` ... `end`: a function that runs as a task of `lib/async/task.aiw`, which the program must `use`: a call returns the handle at once and the body runs when the task is polled. At most six parameters, `ret` with one value, no `tail`; its variables and locals live in the record of the task.
- `await h as x`, `await name a b as x`: the result of a task or event of `lib/async/task.aiw`. A first word that is a variable or a global name (or a number or expression) is the handle; any other name is a function, called like `call` and its first result awaited. In an async function the task waits and goes on there later; elsewhere tasks are polled until the result is there. A call of the function `await` of the program; `as` optional, one name.
- `tail name a b`: calls a function and returns its result, releasing the current frame first; inside a function only, no `as`, at most six values. The target has as many results as the function the `tail` stands in; a function without a `ret` has those of its target. In a function that has a `local` the frame is kept until the callee has returned (a call and a return), since the callee may hold the address of the local.
- `call name a b as x y`: calls a function with as many values as it has parameters; `as` is optional and takes one name per result, at most as many as the function has; the function may be defined later.
- `ref name as p`, `callp p a b as x`: the address of a function, and a call through an address, unchecked.
- `spawn name a b as h`, `join h as x`: a task, the function `name` with up to five values (count checked), and the wait for its first result; `h` is its handle, joined exactly once. They are calls of the functions `spawn` and `join` of `lib/std/task.aiw`, which the program must `use`.

Arguments are 64-bit integers (decimal, `0x` hexadecimal, or either after `-`; one that does not fit is `number too big`), string literals, variables, global names (`buf`, `data`, `var`, `const`) or expressions: values joined by `* / %`, `+ -`, `<< >>`, `&`, `^`, `|` and the comparisons `== != < <= > >=`, tightest first and left to right, with parentheses, written without a space (`b+8*(n-1)`), not where a name is required and not for the number of `sys`; a string is two arguments, address then length, in `sys` and `call`, and its address alone in every other statement. `\xHH` in a string is the byte with that hexadecimal value. `as name` at the end of a statement keeps its result in a variable; that and `name=expression` are the only ways to set one besides being a parameter. A variable may only be read where every way to the line assigned it, and a jump back to a label must have assigned what the label had (`unassigned variable`). `as` is required on everything that produces a value, forbidden on stores, jumps and `ret`, and optional on `sys` and `call`. Variables are 64-bit, at most 64 at top level and 64 in each function (parameters included). Six registers hold them: at top level the first six variables, the rest live in memory cells; in a function a register is reused once its variable is no longer mentioned, and a variable without a free register lives on the stack. A function sees only its own variables and labels; `buf`, `data`, `var` and `const` names are global; a `buf` or `data` may be declared after its uses, a `var` or `const` must come first. At top level variables and global names share one name space; inside a function a parameter or variable hides a `buf`, `data` or `const` of the same name from its definition on, while `as` on a `var` name writes the cell. Labels and functions each have their own name space, with no limit on their number; keywords are only special at the start of a line. Tokens are separated by spaces or tabs only and may not touch; lines end with LF or CRLF; any other separator byte is a syntax error. `#` comments to end of line; a CR in a comment must still be followed by LF. Execution starts at the first line and `exit(0)` is appended, as the syscall `exit_group`, which ends every thread; `sys exit` ends only its own.

## Compiler architecture (`compiler/`)

`compiler/ailc.aiw` is the file given to the compiler: the `var`, `const` and `buf` declarations, then one `use` for each file of functions, then the top level, then the `use` of the tables. What depends on the platform an executable is for, beyond the instructions, is in `compiler/<target>/target.aiw`, which the source names as `use "target:target.aiw"`, and the runtime of that platform as `use "rt:source.aiw"`: `target` and `rt` are packages, and the Makefile tells each compiler that compiles the source which directories they are (`PKGS`, for `TARGET := linux-x86_64`). A target file has the header as the data `thdr` and its length `thdrn`, where the code starts in a line of the cache (`talign`), the bytes of the first line of the runtime that `fin` may make do nothing (`tbootn`), whether `sys` means anything (`tsys`), the bytes an image may have, which `fin` reports `buffers too big` above (`tmax`: 2 GiB less one byte on Linux, 0x77000000 for Windows, which loads no larger image; `tests/win.sh` compiles a program at that size and one a page above), what every program needs of the state of the runtime (`tstate`), the row of `ccall` without its name (`tccrow`), `tstart`, which writes the header into the output, and `tfin`, which writes the sizes into the header and returns the bytes of the file to write. A function goes in the file of its section; a new file is a `use` line where its code is to stand, written as `compiler/<name>.aiw`, and a name in `SRC` of the Makefile. The order of the functions is the order of the code in `build/ailc`.

`docs/compiler.md` explains it at length. One pass over the top level and two over each function, with no AST; the symbol tables are a variable table with 64 entries per scope, a table of global names, a label table and a function table, and the only fixups are jump and call displacements: it reads all of stdin into a buffer, emits machine code into an output buffer as it scans, and writes the buffer once at the end. Buffers never grow: the source may be 8 MiB (`inmax` is one byte more), every table is a `buf` sized from that for the shortest line that adds an entry, as a plain number with the count in its comment, and the output is 16 times as large and checked by `ochk`; untouched pages cost nothing. The largest table, the nodes of the hash of names, is no `buf`: the var `hnodes` is the address of `hnsz` bytes that the top level takes with `alloc` when it starts (`no memory`, status 2, when it gets none; `tests/io.sh` with a limit of memory), because Windows loads no image above 0x77000000 bytes and the compiler for Windows has to stay below that, which `tests/win.sh` checks in the header, since Wine loads any. When an entry changes its size or a shorter line can add one, change the `buf`.

- **The top level is the state machine**, its states labels that jump to each other (`next`, `tokend`, `arg`, `num`, `str`, `ident`, `atname`, `capture`, `usedef`, `uend`, `bufdef`, `localdef`, `vardef`, `constdef`, `datadef`, `labdef`, `jtarget`, `fndef`, `fnend`, `blkend`, `elsedef`, `fin`), and uses only the variables `c d r f p q`, which have registers; a seventh would work but live in memory. Everything else is a function, in one of the other files.
- **Global state is in `var`s**, since a function sees no top-level variable: `ip` and `ie` the input cursor and end, `op` the output cursor, `ai` the index of the next argument of the statement, `nv` the number of variables defined in the current scope, `cur` the row of the statement, `ns` and `nl` the name read last, and the counters under their own names (`nbufs`, `infn`, `nfix`, ...). `as` on one of those names writes the global, so no function may use them for a variable of its own. The tables are buffers (`vars`, `globs`, `labs`, `fixs`, `funs`, `calls`, `refs`, `chks`, `blks`); an entry holds all the fields of its name.
- **Errors are calls that never return** (`call err`, `call edup`, ...): a function of three lines per message sets the name at fault (`ename`, `enamel`) or drops the place and calls `die`, which writes the pieces to stderr. `ok` and `no` are a syntax error unless their value is non-zero or zero. A lookup returns -1 for a name that is not defined. The place comes from `epos`: 0 means the input cursor in the unit `curunit`, -1 nowhere, anything else an address in the source, which the routines that run after parsing set from the name in their entry (`resolve`, the loops of `fin`; a `chks` entry carries the position of its statement). A new error needs its function and a line in `docs/language.md`.
- **Units**: a `use` reads its file into `in` behind everything read so far (`srcend`), pushes cursor and unit end on `ustack` and scans the new bytes; `uend` pops at the end of a unit or goes to `fin`. `uses` holds the paths seen. A function may not span units.
- **Output is a complete ELF64** emitted by the compiler itself: a 176-byte header template (ELF header plus two `PT_LOAD` segments) is copied in first, the code of the runtime follows at file offset 176, and the code of the program follows that. The file is `ET_DYN`: position-independent, loaded anywhere, with no address in any instruction. The first segment is the file, R+X; the second is R+W, has no file bytes, starts on the page after the code and holds the var cells and then the buffers. Its start (`rwstart`) is known only in `fin`, which fills in the `rel32` of every use recorded in `refs` and keeps the image within 2 GiB .
- **Statements are rows of `optab`**: keyword, operand count, two flag bytes and instruction bytes (`cur` points at the count, so the flags are at `+1`, the code length at `+3` and the code at `+4`). The flags are numbers in `compiler/tables.aiw`; `docs/compiler.md` names the bits. All eight of the first byte are taken (1 `AS_REQ`, 2 `AS_NONE`, 4 `IS_SYS`, 8 `IS_JMP`, 16 `IS_CALL`, 32 `IS_RET`, 64 `IS_LEN`, 128 `IS_MEM`); `IS_AT`, `IS_REF`, `IS_PTR`, `IS_IF`, `IS_TOP`, `IS_LIB`, `IS_AWT` and `IS_RT` are the bits of the second, which is full too. A first byte of 255 marks a statement parsed on its own, numbered by its operand count: 1 `fn`, 2 `buf`, 3 `end`, 4 `label`, 5 `data`, 6 `var`, 7 `const`, 8 `local`, 9 `use`, 10 `else`, 11 `while`, 12 `async`, 13 `ccall`, 14 `base`; `next` has a `jeq` per number and falls into `whiledef` for any other. `ccall` goes on as a statement whose row is `tccrow` of the target file (label `stmt`), and `base` writes its `lea` and goes on with the row `rowas`, which only wants an `as`. Operands go through the same parser as syscall arguments, so they land in `rax` and `rdi`; `eop` then copies the row's bytes where `sys` gets its `syscall`, and the result is left in `rax` for `as` (the statements that only compute or compare take another way, see Expressions). `kw` finds the row of a keyword.
- **The runtime** (`docs/runtime.md`, `rt/`): the services of the platform, written in AIL: `rt/linux-x86_64/rt.aiw` (functions `rt_<name>`; first line `stack rt_state`, second a jump over the functions to `label rt_go` at its end) and `state.aiw` (the buffer `rt_state`) are source that the compiler has as data (`rt/source.sh` writes `build/rt/<target>/source.aiw`: `rtsrc`, `rttail`, without comments) and compiles with every program, the first as a unit in front of it (`rtunit`, `rtready`, which fills `rtfn` and `rtfl` from the table `rtnames`: service, number, values, results, what it needs of the state; and pads the code to 48 in a line of the cache) and the second behind it (`uend`, `rtt`, `rtbss`); their text is in the 64 KiB of `in` beyond `inmax`, and the tables that keep entries to the end have room for theirs. A statement that is a service (`IS_RT`: `rt`, also `IS_SYS`, whose name `rtname` reads; `args`, `alloc`, `free`, whose one byte of code is the number of their service) becomes a call of its function in `next` (`rtcall`; `rtend` checks at its end what the row of the service says), compiled in place where a call is, so `rt write` in a function is its system call. `fin` ends the program with a jump to `rt_exit`, makes the first line of the runtime do nothing if no service that reads the stack was called (`rtuse`), and ends the writable segment before the state if none keeps anything there. Every name of the two files starts with `rt_`, which no program uses. It was written in C first (an image in every executable, removed on 2026-11-26 after both passed the same tests). A new service is a function in the `rt.aiw` of each platform, a row of `rtnames` and a line in `docs/runtime.md` and `docs/language.md`; `tests/tables.sh` holds `rtnames` and the rows together, the `rt_*` tests run the services, `tests/rt.sh` checks how the runtime stands in an executable and that `lib/` has no `sys`, and in `tests/insn.cases` a call of a service is `e8........` and a distance to the writable segment stands between `<` and `>`, moved by `tests/insn.sh` as far as the runtime moves the segment.
- **Windows on x86-64** is a second target (`docs/runtime.md`): `compiler/windows-x86_64/target.aiw` (a header of 448 bytes, the import tables in the second page, the code from 8192 on, the file filled up to a page, the memory of the program a section without bytes; a byte of the file is at the same place in memory; `tfin` writes the sizes and the number of sections; `tsys` 0, so `sys` is an `unknown statement`; `tstate` 2, the state always kept; `tccrow` passes the values of `ccall` as Windows wants them), `imports.list` (the functions of Windows the runtime calls) and `imports.sh` (awk: the import tables as the data `timp`, and for the runtime a `const rt_i_<function>` with the place of each address), and `rt/windows-x86_64/rt.aiw`, whose services call those functions through `rt_api` (`base`, the place, `ccall`). `make build/ailc-windows-x86_64` builds the compiler for it, which runs here; its target package is `build/target/windows-x86_64`. `tests/win.sh` runs it under Wine (or prints `skip`): hello, the compiler compiled for Windows compiling its own source to the same file, the bytes of `tccrow`, the services of processes with programs of Windows (`tests/win/`), and one in twenty of the tests without `sys` (`all` for every one), but for those in `tests/win.skip`. The runtime of Windows has every service; `docs/runtime.md` lists what is not as on Linux behind them (a poller of sockets alone, made of `WSAPoll` and a note of what was said to be ready; descriptors as numbers of the runtime, 256 of them; `start` by one line of arguments). A test under Wine is tried twice before it has failed. The tests of the list `always` there are run whatever the count, and one of them that does not compile, has no `.out` or source, has a `sys` or is named in `tests/win.skip` fails the suite; another test that does not compile is left out. A service that the runtime of a platform lacks is an `unknown service` there. A file must not be named like a script beside it without `.sh`: make would write the script over it.
- **Syscall names**: `sname` reads the number of `sys` when it is a name: a const of the program, or else an entry of the table `sysnames` (length, name, two-byte number). A syscall added there is added to the list in `tests/tables.sh` and to the table in `docs/language.md`.
- **Arguments** are emitted by `mov` into the register of the argument position (rax, rdi, rsi, rdx, r10, r8, r9) in the shortest of three forms: `mov r32, imm32` from `regtab` below 2^32, `mov r64, imm32` when sign extension gives the value, else `mov r64, imm64`. `rdnum` reads every integer and reports `number too big`. A fixup of `refs` relies on the first form and takes the address of the `imm32` from `immpos`, since a `push` may follow the `mov`.
- **Variables** live in the generated program's `rbx`, `rbp`, `r12`, `r13`, `r14`, `r15` (table `varnum`) or in memory. The table `vars` stores each name as a pointer into the input buffer plus a length; its first half is the top level and its second half the function being compiled (`infn`), and `defvar` finds or adds a name in the current half. `vplace` gives the place of a variable and `vmov` the `mov` between it and a register (`mrr`, or `emem` for a cell or a stack slot). At top level variables 7 to 64 get a cell of their own (`topcell`, a cell number).
- **Functions are compiled twice.** `fndef` snapshots the cursors and counters in the vars `sip` to `sdr`, `snk`, `snu` and `snh` and sets `pass` to 1; that pass emits throwaway code, reports every error and records per variable its first and last mention (`vfirst`, `vlast`) and per backward jump a loop (`loops`, from the source position in the `labs` entry). At `end`, `alloc` stretches every range that meets a loop to the loop's end, then weighs each variable by its mentions, which the first pass noted in `vms` (`vment`; one in a loop counts 8 times for each loop around it, `vwt`), and gives the variables, the heaviest first, each the first register or stack slot in which no variable placed before is in use while it is (`fnloc`, `fnslots`); `fnend` restores the snapshot and jumps back to `fndef` with `pass` 2. Anything a statement adds to compiler state inside a function must be in the snapshot, or it is added twice. Slots are `[rsp + 8k]`, reserved after the pushes and released before each return by `frame`; `emem` writes the distance in no byte, one or four, and a slot just stored (`slotp`, `slotr`, `slotpos`) is not loaded again at the same output position, a note that a label, the end of a block and a body compiled in place forget like `xflg`. A `local` is a variable with an offset in `vlocal` and no place: `vplace` gives its distance from `rsp`, above the slots, and reading it is a `lea`; the frame is `8 * fnslots + fnlocal`. `clrloc` must not run between the first pass and `alloc`.
- **Buffers** are places in the writable segment (table `globs`, total in `bsssz`). A use of a buffer or data name is `lea reg, [rip+rel32]` from `elea` plus a `refs` entry of kind 0; the entry holds the distance from the first buffer, or for data the file offset. The same table holds every global name, with its kind (address, var or const), and is sized from the source limit; `newglob` enters a name after the duplicate checks. A `var` is a numbered cell at the start of the writable segment, read by `ident` with `mov r64, [rip+rel32]` and written by `capture` with the store form, both through `emem`, which records a `refs` entry of kind 3 with the cell number. A `const` keeps its value in the size field.
- **Expressions**: an argument whose token starts with `(` or has, after its first byte, a byte that no name or number has (`excomp`) goes from `arg` to the state `earg`; every other token takes the old paths, so sources without expressions compile to the same bytes. `exparse` reads it with two stacks and no recursion (`exs` operators and open parentheses, `exv` values with what is known of each) into `ex`, a list of 32-byte nodes in stack-machine order: number, global name plus number, variable, var cell, or operator with the node of its left operand, the right one being the node before it. `exred` applies an operator and folds two numbers (`exfold`) or a name and a number; `exprec` gives the binding strength, `exname` resolves a name as `ident` does, `xgen` computes what is left as a stack machine whose stack the compiler keeps in `exv`: a number, variable, var or address stays what it is until its operator comes, which takes a number as an immediate and a variable in its register or in memory (nothing in an expression assigns, so that is safe), a computed value sits in a register from `xfree` (scratch registers that hold no value of the statement, never `rcx` or `rdx`; order in `xord`, `xpref` first) or is pushed when none is free (`xalloc`, `xspl`, `xpop2`; `pushed` kept exact). `xop` picks `xarith` (`+ - & ^ |` and `imul`, with `reg`, `imm` or memory as second operand, as `xsrc` classifies it; `xmuli` for variable times number: `imul`, or for 3, 5 and 9 one `lea` that also takes the number the next operator adds or subtracts, by `xgi`, `xgh` and `xgskip` of `xgen`), `xshift` (immediate count, or `rcx`), `xdiv` (shift or mask for a power of two, else `rax`/`rdx`, `xtake`) or `xcmpv` (`xcmp`, `setcc`); opcodes are in the table `xopc`, encodings are the shortest, as an assembler writes them. `xfin` puts the result in its register. `exarg` makes the result the next value of the statement, with the registers of earlier values out of the free set and `rax`/`rdx` (if it divides) or `rcx` (if it shifts under `callp`) pushed around the computation, and copies what is known of it to `opd`. **The statements that only compute or compare are compiled like expressions**, unless their line has a string: `xclass`, called in `next`, sets `xst` to 1 for `set` and the sixteen statements whose operators an expression has (`xso`; rows in `xrows`), 2 for those that compare two values and jump or open a block, 3 for `jz`, `jnz`, `if`, `ifz` (and `while`), 4 for the loads and 5 for the stores. `arg` then sends each value to the state `xarg`, which only parses it (`exparse` on top of the values before). At `as`, `xcap` applies the operator with `exred` and stores with `xstore`, as `exasn` does, so `add a b as x` and `x=a+b` are the same bytes; at the label or the end of the line, `xjcond` compares the two sides where they are (`xcmp`) or tests the one value in a register (`test reg, reg`; a value that ends in `&` with a number or `%` with a power of two is not computed, its left side is tested with the mask, `test bl, 1`) and sets `xskip` so that `eop` copies only the jump of the row; for a statement of kind 3 whose value is a comparison it first makes the statement the row that compares and jumps (`iflt`, `jge`, ...; name built in `exnm`). A load ends in `xmload` and a store in `xmstore` (before `eop`, which still runs `memchk` on what they put in `opd`): `xaddr` computes the address as base, index and number (`xmb`, `xmx`, `xmd`: a number added last, then a variable with a register added last, alone or times 2, 4 or 8 or shifted left by 1 to 3, the power of two in `xms`, the rest in a register), and `xmins` writes one `mov` or `movzx` with that operand (`erexm`, `emodm`), a store of a number that fits as an immediate. The instruction bytes of those rows are only used by lines with a string. An assignment is found in `next` by `exasg` before the keyword lookup and compiled by `exasn` (state `asgn`), which defines the variable first (`defv`, `defvar` for a name already read) and stores as `capture` does. A variable with a register is computed there (`xtr`): if no variable of the expression lives in that register it joins `xfree` as the preferred one; otherwise only the last operator (`xlast`) writes it, in place when an operand lives there (`x+=1` is `add rbx, 1`) or after loading the left operand, unless the right one is in it (`xdst`, `xint`, `xswap`); `xtarget` sets `xtin` and takes the register out of `xfree`. `movi`, `lear` and `xld` load into any register, where `mov`, `elea` and `ldvar` load into the register of the next argument; `orr`, `ori`, `rexw`, `modrr`, `epush`, `epop` and `esetcc` encode for any register.
- **Known addresses**: `opd` (first two values of the statement) and `vk` (each variable of the scope) hold what is known of a value: a number, a global name plus a number, or a string. `prop` carries it through `set`, `add` and `sub`, which it recognises by their row bytes; `clrvk` forgets at a label and at `end`. Rows flagged `IS_MEM` (loads and stores; width from the last letter of the keyword) go through `memchk`: a string is checked at once, a name is recorded in `chks` and checked by `fin` against the declared size of the buffer or the run of the data name (`runend`), reporting `invalid access`. `nchks` and `nruns` are part of the function snapshot.
- **Assigned variables**: `asg` is a 64-bit mask of the variables assigned on every way to the current line; `ident` checks it on a read, `capture` and parameters set it. A jump stores it in its `fixs` entry; `label` ands the masks of the jumps seen so far into it (`labasg`) and keeps the result in the entry of the label; a backward jump must contain that mask. After `jmp` and `ret`, `godead` sets all bits until the next label; a label reached only from below starts from `jmask`. `fndef` and `fnend` save and restore the three in `tasg`, `tdead` and `tjmask`.
- **Finding names**: labels, functions and global names go through one hash (`buckets`, `hnodes`; `hfind`, `hadd`), keyed by kind, scope and name; `llab`, `lfn` and `lbuf` wrap it. A table entry needs a node to be found: `globdone` adds the one of a global name when its statement is complete. Each pass over a function has its own `scope` number, the node count is in the function snapshot and `hundo` removes the nodes of the first pass. A jump to a label not yet defined keeps the and of `asg` in a pending node, which `labasg` reads.
- **Labels and jumps**: `label` records the output cursor under its name (table `labs`). `jmp`, `jz` and `jnz` are `optab` rows flagged `IS_JMP` whose bytes stop before the `rel32`; the name after their operands is taken as a label by `jtarget`, which appends the name and the `rel32` address to `fixs`. `resolve` fills in every jump of the current scope, backward ones included, and reports `undefined label`; `fin` calls it for the top level and `end` for a function. Both tables are sized from the source limit and cannot overflow.
- **Blocks**: rows flagged `IS_IF` end before the `rel32` of the opposite jump; at the end of such a statement `arg` pushes the `rel32` address and `asg` on `blks`. `end` with a block open (`nblk` above `blkbase`) goes to `blkend`, which fills in the jump and merges `asg` with the recorded mask; `else` (`elsedef`) emits a `jmp`, retargets the entry and remembers how the first part ended. No label is created. `while` (`whiledef`) forgets `vk`, notes the place of its value in the source (`wsrc`, `whead`) and continues as the statement `if`, whose `blks` entry (40 bytes) takes along the first line of the loop and `wsrc`. `blkend` then checks `asg` against the mask of the head as for a backward jump, adds the loop to `loops` in pass 1, and reads the value again from the source as that of a `jnz` (`wend`, `wip`, back to `arg`); `wclose` writes that test and the jump back to the first line (`wbody`), lets the jump of the head land behind it and restores the cursor and `asg`. A value that is two comparisons joined by `&`, without a division, is two jumps at each end (`xjcond`: the first comparison with a jump of its own, whose `rel32` is `xsc`, filled in by `wclose` at the end and through the 4 bytes at 16 of the `blks` entry by `blktop` at the head); every other value with `&` is computed. A loop thus tests at both ends and a round is one jump. The first line of a loop starts at a multiple of `lalign`, 64, in the file: `pad` writes instructions that do nothing (table `nops`) behind the jump of a `while` head, and in the second pass of a function before a label that a jump of the first pass went back to (a byte of `lback` for the label's number, set by `jtarget`, read and cleared by `labdef`, not in a body compiled in place, whose labels have the numbers of later labels of the function); labels of the top level and of bodies compiled in place are not padded. `fnpad` counts the padding of a function, which the limit `inlsz` leaves out. `exname` never moves a last mention back, because of that second reading, and `lvar` then sees only the variables there were at the head (`wnv`, kept in the `blks` entry), so a variable defined in the loop does not hide the global name the value named. **The zero flag**: `xarith` (not `imul`) and `xshift` by a number note the register of their result and the output cursor in `xflg` and `xflgpos`, and `xjcond` leaves out `test reg, reg` when that register is tested with the cursor unmoved (`i-=1` then `jnz i l` is `sub rbx, 1` / `jnz`); `label` and the end of a block forget the note, being the places control reaches without a byte written.
- **Functions**: `fn` emits a `jmp rel32` over the body (patched by `end`), then the entry: one `push` for each of the variable registers the function uses (`fnregs`, counted by `alloc`; `pushlen` gives the bytes), `sub rsp` for the frame if any (a frame of a page or more through the template `probe`, which touches every page), and one `mov` per parameter from its argument register (`rax`, `rdi`, `rsi`, `rdx`, `r10`, `r8`). It saves `nv` and remembers where the function's labels and jumps start (`labbase`, `fixbase`); `end` emits `xor eax, eax` and the epilogue, resolves the function's jumps and cuts `labs` and `fixs` back, which is what makes labels local. `ret` is an `optab` row (`IS_RET`) whose bytes are the six `pop`s and `ret` (also the table `retc`); `popskip` says how many of those bytes to leave out. `tail` has the flags of `call` and `ret` and the bytes of the pops plus `E9`; in a function with a `local` (`fnlocal`) `eop` writes `E8`, the entry of `calls`, and then the return from `retc` instead. A function with a `tail` and no `ret` has the results of its target: its count in `funs` is 0 until `tailres`, called by `fin`, passes the known counts back along the tails (`tails`, `tailq`; the `calls` entry of a tail carries its function with the bit 31 set), and `fin` reports `wrong result count` for a `tail` whose target has another count than the function it stands in. `call` is a row flagged `IS_CALL`: values after the sixth are loaded into `r11` (row 7 of `regtab` and `argnum`, chosen by `aidx`) and pushed by `anext`, which counts the bytes in `pushed`; `vplace` adds `pushed` to stack-slot distances and `eop` emits `add rsp` after the call. The callee loads those parameters from above its frame, which needs `fnnpar` from the first pass. `next` reads the function name into `cn` and `cl`, and `eop` appends name, `rel32` address and value count to `calls`, which `fin` resolves against `funs`, reporting `undefined function`, `wrong argument count` and `wrong result count` (the results of the function against the names after `as`, which `capture` collects in `caps`). A `call` in a function, of a short function before it, is compiled in place (`inlchk`, `inlopen`, `inlclose`): the callee was found fit at its end (`finl`: code of at most `inlsz` bytes, at most six parameters, no `local`, `tail` or task, no variable in a stack slot, and a body that declares no global name; what the body adds to `calls`, `refs` and `chks`, by its calls and the global names it uses, is in its `finl` entry of 48 bytes, and `inlchk` refuses where the room those tables have for bodies behind the room of the source's own lines (`ilroom` entries of `calls`, twice that of `refs`, half of `chks`; taken: `ilc`, `ilr`, `ilk`, in the function snapshot) would not hold it, which also makes the function with that call unfit (`ilfull`)), the cursor goes to its parameters and reads the body as lines of the caller, with `vlo` hiding the caller's variables from `lvar`, a scope of its own for labels, every mention counted at the place of the call (`vpos`) and each `ret` a jump to the end of the body; a parameter the body never assigns, given a variable by itself, is that variable (`valias`). The variable numbers are used again after the body (`vhi` is how many `alloc` places). A function with such a call is fit itself, so bodies are read in bodies, up to four deep (`ildp`): `ilpush` and `ilpop` keep the state of the outer ones in `ilstk`, mentions count at the outermost call, in a body only a function that stands before the body's own (`ilfn`) is compiled in place, and the `finl` entry holds `vhi` as the variables and one entry of `calls` more for each call compiled in place (`ilcnt`), since deeper or later such a call may be a call. `ref` is a call entry with the count -1; a row flagged `IS_LIB` (`spawn`, `join`) calls the function named like its keyword, whose place in the source `next` keeps in `kwn` and `kwl`, so the program must define it (`lib/std/task.aiw` does): `join` is otherwise a `call`, and `spawn`, which also has `IS_REF`, reads a function name, starts its values at position 1 and has `eop` write `lea rax, [rip+rel32]` with a call entry that carries the count of the values, so `fin` checks it, then `call rel32` with an entry of count -1; `callp` (`IS_PTR`) puts its first value in `rcx`, row 8 of `regtab`, and is not recorded.
- **Async functions**: `async` (`asydef`) requires `fn`, sets `fnasy` and enters `fndef`; `fnend` clears it after pass 2. `alloc` then gives a slot and no register to every parameter and to every variable with an `await` in its range (`awts`, noted by `eop` in the first pass at `awpos`, behind the values of the statement and before its names after `as`), and one of the five registers behind `rbx` to the others; `vplace` returns distances from the record of the task (64 bytes, the slots, the locals) without `pushed`, `emem` writes kind 2 as `[rbx+disp8]` (`disp32` from 128) and `frame` nothing. `asyent` writes the entry: the code a call runs, which pushes the parameters, calls the program's function `async` (a `calls` entry named by the word in the source, `asyn`/`asyl`) with the record size and the address of the poll function, and pops the parameters into their slots (`asytst`); then the poll function (`asypoll`), which pushes `rbx` and the registers of its variables (`fnregs`), sets `rbx` and jumps to the address at 8 of the record if any. `ret` and `end` copy `asyret` (result to 16 of the record, return 1) and pop those registers (`asyout`, `asypops`), as the return of 0 in `asysus` does. `await` is a row with `IS_CALL`, `IS_LIB` and `IS_AWT`: `next` takes a first word that is no variable and no global name as a function (`awf`, `cn`, `cl`), and `eop` writes its call, removes pushed values, then with the handle in `rax` calls the program's function `await`: with `xor edi, edi` outside an async function, and inside one with `asyawt` before (handle to 48 of the record, the address of the next instruction to 8, handle and record as the two values) and `asysus` behind (return 0 if the second result is 0). A task leaves and enters only there, at a statement boundary.
- **Strings and data** are inlined in the code stream behind a `jmp rel32`; a string is addressed by a `lea` whose distance is known at once, so no data section or second pass is needed. The code segment is not writable, so they are read-only. `sbytes` copies the bytes of a literal for both. A `data` statement that starts where the previous one ended (`dataend`) appends to it and rewrites that jump (`datarel`) instead of emitting its own; `label` clears `dataend`, so a label after data stays the address of code. The row flag `IS_LEN` makes an operand its length instead of its address, and `IS_AT` makes the first one (`atname`) two values, address and size; the size of a global name is a `refs` fixup of kind 2, the bytes to the end of its object.

Adding a statement that takes values in `rax`/`rdi` and leaves a result in `rax` means adding a row to `optab` in `compiler/tables.aiw`, with a case in `tests/insn.cases`; anything else needs a row with flags 255, its `jeq` in `next` and its own state ending in `eol`. Either way add tests for what it accepts and rejects. The source of the compiler may not use a new statement until a seed that understands it is pinned in `seed/MANIFEST`. Forward references go through a fixup list: `fixs` holds the `rel32` jump displacements to labels of the current scope, `calls` the `rel32` displacements of calls, `refs` every place that `fin` must fill in once the layout is known: kind 0 the `rel32` of an address of a buffer or data name, 1 and 2 the `imm32` of a length (`len`, `at`), 3 the `rel32` of a var cell; `fin` resolves `refs` last and reports `undefined variable` there.

**The read-only tables** (ELF header, statement rows, register tables, syscall names) are `data` lines in `compiler/tables.aiw`, which `compiler/ailc.aiw` names with `use` in its last line. That file is their definition and is edited by hand, one row a line; a row is decimal bytes, so write the instructions, take their bytes from `tests/insn.sh hex`, and add the case that checks them.
