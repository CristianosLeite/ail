# Stage1 self-hosting

**Summary.** `stage1/ailc.ai` is the stage0 compiler translated to AIL, routine by routine. It
emits the same bytes as stage0 and compiles itself to an identical file. `docs/stage1.md`
describes its structure; this page records the decisions, how it was verified and what it showed
about the language.

## Facts
- Written on 2026-11-19 against the language as it was: `stage0/ailc.s` was not changed.
- About 1170 lines and 17 KiB of source, far below the 65536-byte limit; `build/ailc1` is
  12478 bytes (stage0 is 13352 as linked by `ld`).
- The first build already reached the fixed point: `build/ailc1` (by stage0) and `build/ailc2`
  (by `ailc1`) are the same file.
- `tests/stage1.sh` compares the two compilers on stdout, stderr and exit status for the source
  of all 220 tests and 5 examples, then compares `ailc1` with `ailc2`. `make test` also reruns
  `tests/run.sh` and `tests/io.sh` with `AILC=build/ailc1`: 674 checks in all since `io_short_write` was added.
- Mutations of a scratch copy of stage1, with the number of `tests/stage1.sh` failures: one byte
  of the statement table 11; `num` without its 32-bit mask 1; `p4` clearing the four bytes after
  the patch 67; argument limit 7 raised to 8 in `eop` 2; buffer limit 16 raised to 17 2; `crlf`
  accepting any byte after CR 4.
- A differential fuzz, not in the suite: 20000 sources made from test and example sources by
  one to four random edits (inserted tokens, deleted spans, random bytes, truncation, copied
  spans, two sources joined) gave no difference between the compilers.
- The read-only tables were generated by a script from the `.rodata` bytes of `build/ailc.o`
  (header template through `exit0`), with four rows added to the statement table before its
  terminator. The script is not in the repository; the numbers in the source are the tables now.

## Why
- **No change to stage0 (chosen by the user):** the seed stays stable and the roadmap asked for
  extensions only if writing the compiler showed a need. It showed friction, not a need.
- **Full parity (chosen by the user), down to the bytes:** identical output makes the test of
  stage1 a comparison with stage0 on any source, including random ones, instead of a second set
  of expected results.
- **A translation, not a redesign:** the order of checks in a routine decides which message a
  source with two faults gets; following stage0 line by line gets that right by construction.
- **State in buffers:** a function sees no top-level variable and returns one value, and a buffer
  name is the only global name. Hot cells have a buffer each, cold ones share `st` behind the
  accessors `g` and `s`, because sixteen buffers is the limit and all are used.
- **`pk` returns 256 at the end of the input:** the "at the end?" and "which byte?" tests of
  stage0 become one comparison, which fails for every character class at the end.
- **Table entries carry all fields of a name** (stage0 has parallel arrays): one buffer per table.
- **`fn`, `buf`, `end` and `label` are rows of the statement table, flagged 64:** `label` does
  not fit a 32-bit immediate, so comparing those names in code would be longer than a table row.
- **Errors are functions that exit:** labels are local, so a function cannot jump to a common
  error exit, and a message can only be written by a `sys` holding its string.

## How to apply
- A language change goes into both compilers; `tests/stage1.sh` fails while they differ on any
  test. Add the tests first, change stage0, then stage1.
- Changing a statement's bytes in stage1 means changing decimal words after `store op ro`; adding
  or removing bytes moves the offsets 490, 531, 541, 555, 562 and 568 used in the code.
- Append with `e4` only; patch with `p4`. `e4` clears the four bytes after the ones it writes.
- A variable in stage1 may not be named like one of its buffers (`in`, `op`, `st`, `ns`, ...):
  that is `duplicate name`.
- To check a change beyond the suite, rerun a differential fuzz as described under Facts.
